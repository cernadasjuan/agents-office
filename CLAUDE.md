# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

```bash
pnpm dev        # Start Vite dev server (opens browser)
pnpm build      # Production build
pnpm preview    # Preview built output
pnpm typecheck  # Type check without emitting

```

## Design rules and roadmap

Read `docs/design-principles.md` before any feature change: it lists the design rules (P1 to P15, S1 to S8) and the rules for every change. `docs/roadmap.md` holds the tiers, the planned slices and the conflict matrix.

## Architecture

3D office visualization (Three.js + Vite) that shows running Claude Code agents as animated stick figures. Each agent's activity is detected from real session data and mapped to a physical station in the office.

### Data Flow

```
~/.claude/sessions/*.json → server/agentDetector.ts → GET /api/agents → AgentPoller (3s) → AgentManager → 3D Scene
```

1. **Server** (`server/`): Vite middleware plugin reads Claude session files, validates PIDs, infers activity from transcript `.jsonl` tool_use blocks (language-agnostic), and detects active subagents
2. **Polling** (`AgentPoller.ts`): Fetches `/api/agents` every 3 s, one request at a time with a 5 s limit, and reconciles with AgentManager (add/remove/update). If the API fails (network error, HTTP error, bad JSON), the current scene stays and the failure counts in `pollHealth` (`{ loaded, lastSuccessAt, failures }`); the third `start` argument gets it after every finished poll (a poll skipped while one runs reports nothing). The first good answer always calls `onUpdate`, also for an empty office, so the panel loading text goes. `src/ui/freshness.ts` turns the health into the panel footer (`#panel-footer`): "Loading agents…", "Updated N s ago", amber with "retrying" from `FRESHNESS.warnAfterFailures` (2), red "Server not reachable" from `downAfterFailures` (5). `FreshnessFooter` ticks once a second and only changes text, so it requests no frame. Subagents get a `>> ` prefix in their name
3. **Agent Management** (`AgentManager.ts`): Creates StickFigures and handles their lifecycle. Where a figure goes is the layout's decision (`src/layout/`): `LayoutStrategy.seatFor(agent, previousActivity)` returns a `Seat` (position, look-at, optional forced posture) or null to stay. `ActivityLayout` is the original behavior. `registry.ts` picks the layout from `?layout=`, then browser storage, then the default; Shift+L (`isLayoutSwitchKey`) then a `window.confirm` (`confirmLayoutSwitch`) cycles layouts, one L alone does nothing. `registerLayout(id, factory, { makeDefault, defaultView })`: `defaultViewFor(id)` is the view a layout opens in (first person unless it says otherwise; the building asks for the overview). Optional fork add-ons in `src/addons/*.ts` register more layouts
4. **Scene** (`Office.ts`): 28 stations across 7 types (the 6 lounge sofa seats are seated idle seats) (implementing, planning, researching, testing, reviewing, idle, meeting). One agent per station. When no station of the right type is free, AgentManager opens an overflow spot on open floor; it never uses a station of another type

### Extension seam (server/seam.ts)

Detection runs as a pipeline: the core `claudeSource` (wraps `detectAgents`), then plugin sources, then enrichers in order, then world providers for rooms and boards. A failing or slow plugin step (2 s limit) drops only its own output; a core failure is a 500. `projectAgents` and `projectWorld` are the only exit: they copy whitelisted, cleaned fields and hash every key with the per-run HMAC. `/api/world` uses the same request checks as `/api/agents`. Plugins live in `plugins/<name>/index.ts` (default export `OfficePlugin`) and load through `server.ssrLoadModule` from `AGENTS_OFFICE_PLUGINS=a,b` or `agents-office --plugin a`. Their browser parts live in `plugins/<name>/client.ts` and register an `OfficeExtension` (`src/extensions.ts`) with `plugin: '<name>'`, so they run only while the server plugin is active.

Plugins in this fork: `plugins/bmad/` (persona hats). Its enricher reads the tool_use blocks of `internal.transcriptPath` incrementally (a per-file offset cache) and `internal.agentType`, and sets persona ids as `badges`. `client.ts` stacks one toon hat per badge on `figure.joints.head` (max 4, then a `+N` marker) and adds the persona names to the label activity line. `roster.ts` is the shared persona list. `pnpm dev:fork` loads the fork plugins.

- **`plugins/github/`**: opt-in with `AGENTS_OFFICE_GITHUB_REPOS=owner/name[,owner/name]`, else it adds nothing. `gh.ts` runs `gh issue list` via `execFile` (5 s, no shell, 60 s cache) and derives the columns. `transcript.ts` finds issue numbers in Bash tool calls. `client.ts` draws wall boards (`KANBAN_BOARD_SLOTS`). `cards.ts` (`IssueCardBatch`) draws the issue cards as badges: slots near shoulder, far shoulder, then the upper arms (near, far, near); "near" is the side that faces the camera, with a margin so it does not flip in front views. All cards of all agents are one world-space geometry with one canvas atlas (one draw call, no shadow, no raycast). The batch chains `scene.onBeforeRender`, which gets the camera after the world matrices update and before the renderer uploads the geometry: each card is placed from its upper arm joint, kept upright (world up) and turned about the vertical axis to the camera. Cards on one side never overlap (they stack down, or up along a raised arm). Each card has a front and a back quad with their own UVs (no mirrored text). A card reads `<repo>#N`; `repo` is the short name the projection keeps only as a plain token (`repoShortName` in `server/seam.ts`), and the plugin sets it only for a configured repository that holds the issue or that the call named. The border is `color`, a label color the projection keeps only as `rrggbb` (`hexColor`); `gh.ts` picks a `wayfinder:*` label, else the first label. `labelIds.ts` adds one `.github-issues` line (textContent, at most 5 IDs, cut on whole IDs) to each floating label on every `agentsChanged`, because the core rewrites the label on a change; a style element from the plugin keeps the line in compact labels. The enricher refreshes the issue cache itself (bounded at 1.5 s, under the 2 s seam step limit), so `/api/agents` has titles and colors without a `/api/world` call first. `pnpm dev:fork` loads the fork plugins.

`plugins/herdr/` (enricher, `pnpm dev:fork`, plus the opt-in focus write action below): reads only the three `HERDR_*_ID` variables from one batched `ps eww` for new session PIDs, then `herdr tab list` and `herdr workspace list` (cached 10 s, `execFile`, 1.5 s timeout); sets a main session name to its tab label and the workspace as group for the session and its subagents; any failure changes nothing. The command runner is injectable for tests.

### Read views and the peek plugin (plugins/peek)

`OfficePlugin.views` offers per-agent read views from the closed enum `VIEW_NAMES` (`server/seam.ts`, today only `peek`). `vitePlugin.ts` always mounts `GET /api/views/<name>?agent=<public id>`: `admit` (same checks as every GET route, POST gets 405), then 404 for a view no loaded plugin offers, 400 for an ID that is not 64 hex, 404 for an agent not in the last `/api/agents` answer (the same server-side public id map as write actions), 500 without details when the view throws. The answer goes through `projectPeek` only: at most 10 lines of 200 characters, masked again with `maskedLine` (`server/secrets.ts`: collapse white space and control characters, 4000-character raw cut, `maskSecrets`, then `cutBeforePlaceholder`, which never splits a placeholder), an optional pinned `question`, up to 10 https assets (no credentials in the URL), skills and repos as plain tokens. View data never enters `projectAgents` or `projectWorld`.

`plugins/peek/` (opt-in, on in `pnpm dev:fork`; breaks S4 by design, see the README): `transcript.ts` (`PeekReader`) reads `internal.transcriptPath` (`.jsonl`, regular file only): the last 2 MB the first time, then only new bytes (4 MB cap per read, else it starts again at the tail; lines over 1 MB are skipped). It keeps per file the last 10 entries (assistant text through `maskedLine`; tool calls as `toolSummary`: the tool name plus a safe token such as the Bash program and subcommand, a file base name, a skill or subagent type, a WebFetch host), assets from tool inputs only (GitHub issue and PR URLs, `gh issue|pr <verb> N -R owner/repo`, GitLab `/-/merge_requests/N` URLs, Jira keys whose prefix is in `AGENTS_OFFICE_PEEK_JIRA`, default `DEFAULT_JIRA_SITES`), skills from Skill calls and repos from Edit/Write/NotebookEdit paths and git write commands (`-C <dir>` or the session cwd), mapped to the git root's short name (a worktree `.git` file maps to its main repository). `question` is the newest entry when it is assistant text and the agent has an attention. `client.ts` registers a card panel (`PeekPanel`): on only while `/api/world` lists `peek`. It loads on selection, then every `PEEK_REFRESH_MS` (5 s) by its own timer while the card shows the agent; a render inside the throttle schedules one trailing load. `hide()` (the card calls it on close or when the panel is not available) stops the timer. A late answer for another agent is dropped, all text goes through textContent, links only for https. `setPeekTextHidden` hides all peek sections (the hook for the private mode, #91).

### Write actions (server/actions.ts)

S7 keeps the API read-only by default. A write action exists only when a loaded plugin offers it in `OfficePlugin.actions` behind its own opt-in. Today there is one: `focus` from `plugins/herdr/` with `AGENTS_OFFICE_HERDR_FOCUS=1`. Without an offered action, `vitePlugin.ts` mounts no POST route, serves no token and adds no header. Rules for every write action:

- The action name is in the closed enum `ACTION_NAMES` (`server/seam.ts`). The route is `POST /api/actions/<name>`, the body exactly `{ "agent": "<public id>" }` (`parseActionBody`). Never a raw ID, a path, text or a command from the browser.
- `admit(..., 'POST')`: loopback, local Host, `Origin` required and equal to the server origin, `Sec-Fetch-Site` same-origin when present. Then `WriteActions.handle`: `X-Agents-Office-Token` (random 32 bytes per server start, from `GET /api/actions/token`, SHA-256 then `timingSafeEqual`) → 403, `Content-Type: application/json` → 415, 10 per minute → 429, body over 1 KB → 413, bad shape → 400, unknown agent or agent without the action → 404.
- The public id resolves to the observation from the last `/api/agents` answer (a server-side map). The agent must advertise the action in `display.actions`. `projectAgents` copies `actions` only for names in `ACTION_NAMES` that the server enabled.
- `OfficeAction.run(observation)` re-checks its target right before it acts and returns `done` (200), `gone` (409) or `failed` (502). Subprocess only through `execFile` with fixed argv, a strict ID pattern and a timeout.
- One audit line per attempt (`time`, `action`, public `agent`, `result`) to `AGENTS_OFFICE_AUDIT_LOG` or `os.tmpdir()/agents-office-audit.jsonl`, mode 0600. Never the token, a raw ID or the body.
- With an action on, every response gets `X-Frame-Options: DENY` and `frame-ancestors 'none'`.
- Tests inject the command runner and the audit path (`auditLogPath` option). Never run a real write command in a test.

herdr focus: the enricher keeps `focusTargets` (observation id → pid, pane id, tab id; a subagent uses its parent's pane) and sets `display.actions = ['focus']`. `run` re-reads `ps eww` for the pid and `herdr pane get <pane>` (same pane and tab), then `herdr agent focus <pane>`, else `herdr tab focus <tab>` when the pane has no detected agent or agent focus fails. `plugins/herdr/client.ts` registers a "Focus in herdr" button in the agent card (`registerCardAction`) for agents whose `extras.actions` holds `focus`; `FocusClient` fetches the token (once more after a 403), and the card shows the result as text. `pnpm dev:fork` sets `AGENTS_OFFICE_HERDR_FOCUS=1`; the request still goes out only on the click.

### Attention (server/attention.ts, src/ui/attention.ts)

A built-in enricher sets `attention` for main sessions: status `waiting` → `waiting` (blocked), `idle` → `your-turn`, with `waitMinutes` from `statusUpdatedAt`. The browser puts each wait in an age band (`attentionBand`, thresholds in the one constant `ATTENTION_BANDS`: fresh under 15 min, aging under 24 h, cold from 24 h). `callsForYou` (fresh) drives the raised right hand (the arm overrides the activity pose; the rest stays) and the amber beacon, for both attentions. `queuesForYou` (fresh or aging) drives the building queue, `countsInTab` (fresh) the tab title (`tabTitleFor`), `compareWaits` the order (fresh before aging, the longest wait first). Without `waitMinutes` each helper keeps the old behavior: beacon and queue for `waiting` only, tab count for both. The label always shows "Waiting for you · N min" or "Your turn · N min". Key N's queue (issue #85): `triageQueue` filters to `queuesForYou` and sorts by `compareWaits`, the same set and order as the panel's needs-you/your-turn groups; `nextInQueue(queue, currentId)` steps to the agent after `currentId`, cycling back to the first past the end, and returns the first agent when `currentId` is null or has left the queue (a cold start, or a selection moved to cold or cleared).

### Fork add-on: building layout (src/addons/building*)

`src/addons/building.ts` registers `BuildingLayout` as the default layout (fork only, tier T3). `RoomPlanner.ts` is pure geometry: 12x12 room slots around the 30x26 hall (first ring of 7, the office first at east-center; later rings shift outward and open toward the inner room), door gaps and wall pieces. `rooms.ts` builds a room in a local frame (`RoomFrame`: depth from the door wall, position along it): floor marked `userData.floor`, low walls named `room-walls`, a `door-frame` group (two `door-post` meshes and a `door-lintel` in the floor color, `doorFrame`), a room label (`roomLabel` in `roomLabels.ts`: a handle object named `room-label` at the room center whose position and scale are the plate pose, text in `userData.roomLabel`, room in `userData.roomRect`; `RoomLabelBatch` (`roomLabelBatchFor(scene)`, one per scene, `BuildingLayout` collects each new room) draws every handle as one instanced billboard quad with a canvas atlas, a slot per label redrawn when the face changes, scale 0 for a hidden or detached handle; a full face (2 lines of 16) and a compact face of 2 condensed lines of 7 (`compactLabelLines`: a longer name keeps its first line and its last word), `roomLabelLines` with " · " as a line break; `userData.applyView` takes the view from the label controller and sets the face and `roomLabelPose`: first person a 0.7 m plate centered at 2.2 m with depth test, overview a plate that grows with `zoomDistance / 40`, capped at `ROOM_LABEL_MAX_WIDTH` and 5 m, drawn on top, compact face unless zoomed in, pointed at or labels: all), furniture and stations from the room plan (see Furniture library below). `markCutaway` puts the walls (and a mission room's closed door) in the `room-walls` static zone with `overviewLower: WALL_HEIGHT`; `markDoorCutaway` puts the door frames in the `door-frames` zone, which drops to `OVERVIEW_DOOR_HEIGHT` (1.2) instead; the hall walls use the `hall-walls` zone with `overviewLower: OFFICE.height`. `roomTitle(kind, earlierKinds, tag)` names a room: lounges are numbered (`Lounge N`), workspace desk rooms are `Desks · <tag>`. `BuildingLayout.ts` keeps per-agent state (home desk, current seat, target, pending trip, queue time): desk work at home, trips to station types after `dwellMs` (4 s), main sessions that `queuesForYou` (or with activity `meeting` and no cold wait) go to `queue` spots at once and are reordered by `compareWaits` in `update()`; a cold wait leaves after the dwell time, subagents use pod spots around the parent desk. An exhausted station type adds a room (`ROOM_STATION_TYPE`), saved in `localStorage` (`agents-office.building.rooms`) and rebuilt on load. The hall side walls are hidden and replaced by `building-hall-walls` with a door per first-ring room.

### Furniture library (src/furniture/index.ts, src/addons/building/furnishing.ts)

Code builds every piece; nothing is loaded from a file. Each piece is a factory in `src/furniture/` (one file per piece or family: `Armchair.ts`, `Tables.ts` with the low table and the credenza, `DisplayShelf.ts`, `FloorLamp.ts`, `Portrait.ts`, `Decorations.ts` with plants, rug, wall art and clock). `PIECES` in `src/furniture/index.ts` lists them all: `PIECES.<name>(args)` returns a `PieceSpec` (`name`, `category`: `station`, `furniture` or `plant`, `create`). A piece faces +z, stands on y = 0 and uses toon materials only (the static merge takes it; the portrait sprite is the one exception). Reuse palette colors that a room already has (`Colors`, the book colors): a new color in the `rooms` zone costs one draw call.

`roomFurnishing(kind, { doorAlong, usersOffice })` in `furnishing.ts` is the one plan per room kind: `pieces` (piece, `a`, `d`, optional `y` for wall pieces, `turn` added to the face-the-door rotation), `spots` (stations: type, position, look-at, posture) and `signs` (the office "You" sign and the queue count). Plans hold positions only; `rooms.ts` builds no furniture geometry and imports no factory: `furnish()` creates each piece (named in `userData.piece`), each spot as a station and each sign. Rules a plan keeps (tested in `tests/furnishing.test.ts`): no standing piece within `QUEUE_SPOT_RADIUS` (0.35 m) of a spot, none in the hall door path (`doorAlong` +/- 1.2 m, depth 0 to 2.5 m) or in the far wall gap an outer room's door may open (a = +/- 1.2 m, last metre). Every room kind keeps that far wall gap clear, checked at every real door position; the library's far-wall shelves sit off-center (or off the wall) to leave it open. The office lounge corner goes to the front corner away from the door (mirrored when `doorAlong < 0`); the office plan is tested at every real door position (0, 1, 2.5, -2.5). Only your office (room 0, `usersOffice`) gets the portrait and the count sign; a second waiting room gets neither. The office queue: 23 spots in five rows 1.3 m apart, 2.3 m between spots, odd rows shifted by 1.15 m, front center first.

The portrait (`createPortrait`): one sprite with a canvas texture over the office door on the hall side, top of the lintel + 0.05 m and up, a neutral silhouette until `applyPortraitImage` draws a picture (cover crop). `src/addons/building/portrait.ts` fetches `GET /api/portrait` once when the building layout starts; a 204 keeps the placeholder, an image fills every portrait, and your office rebuilt later gets the loaded picture (`showLoadedPortrait`). `server/portrait.ts` (`readPortrait`): the path comes from `AGENTS_OFFICE_PORTRAIT` (or the `portraitPath` plugin option, null turns it off); the file must be a regular file of at most `PORTRAIT_MAX_BYTES` (2 MB) with a png, jpg, jpeg, webp or gif extension whose magic bytes match; anything else gives 204. The route uses `admit` (loopback, local Host, same origin, GET). The sign under the portrait (`QUEUE_COUNT_SIGN`) shows "N waiting" for the fresh and aging waits in the queue (`queuesForYou`; a meeting without a wait queues but does not count); `BuildingLayout.orderQueue` sets it, hidden at 0.

### Mission war rooms (plugins/missions, src/addons/building/missionRooms.ts)

`plugins/missions/index.ts` reads `mission.yaml` records (via the `yaml` package, 1 MB cap, 30 s cache) from `AGENTS_OFFICE_MISSION_ROOTS` and provides world rooms (`mission:<slug>`, open unless done or abandoned) with walls (destination, artifact titles, GitHub members, thread kanban) and `sleepers` (one entry per journey session/night_run, its own id and the day it ended, `MissionSummary.sleepers`). Its enricher scans each session transcript incrementally for tool calls that touch `missions/<slug>/` or a `mission <cmd> <slug>` command and sets `roomKey` for the session and its subagents. The building add-on registers a `building-world-rooms` extension: `BuildingLayout.syncWorldRooms` builds any world room in the mission wing (`missionSlot`: two columns north of the hall back wall, rows further north), updates walls each poll, and seats agents whose `extras.room` matches (queue still wins). Locked rooms close their door and take no agents. Each war room has a door frame and a room label with the mission title (`setRoomLabelText` on update); its CSS2D signs carry `data-sign="mission"` and `userData.detailSign` (title and lock sign by zoom or hover, past-sessions count and each tombstone's end-date sign by hover only).

**Tombstones (issue #127):** one ended session, one tombstone (`PIECES.tombstone()`, `src/furniture/Tombstone.ts`: 2 boxes, 2 shared materials, so a room full of them still merges into about 2 draw calls through `StaticMerge`). `missionRooms.ts` keeps a `Map<string, {object, hoverSign, endedAt}>` per room, keyed by the server's own hashed sleeper id (never by position): a session that returns drops out of `next.sleepers`, so its tombstone (and only its tombstone) is removed by id on the next `update()`; a session that stays keeps its same object, not a rebuild. Shown up to `MAX_TOMBSTONES` (12); the rest add to the existing "N past sessions (+N not shown)" sign. A click or hover opens the tombstone card (`src/ui/TombstoneCard.ts`): same CSS classes and dock spot as the agent card (`#agent-inspector`/`#tombstone-inspector` share their rule in `index.html`), same shared selection (`officeSelection()`) — a tombstone id never matches an agent id, so only one of the two cards ever shows; its code is not reused (`AgentCard`'s fields are agent-shaped: activity, wait, actions, panels). A tombstone is pickable the same way a figure is: `OfficeExtension.pickTargets()` (building.ts's `activeBuilding.tombstonePickTargets()`) adds its targets to `ViewController.pickAt`'s raycast; `pickAgent` (`Selection.ts`) now also enables `STATIC_SOURCE_LAYER`, so a merged tombstone's original, still-positioned source mesh (not reparented by `StaticMerge`) is still hit-testable. No fade-in: the rulebook's draft suggested one, but a transparent material cannot merge, so a fading tombstone would cost its own draw call until the fade finished; skipped in favor of the draw-call budget, which every formal AC does require.

### Library and librarians (plugins/library)

The projection whitelist has a `role` token (`DisplayExtras.role`, cleaned like badges). `plugins/library` sets `role: 'librarian'` for subagents whose server-side `agentType` is in `AGENTS_OFFICE_LIBRARIAN_TYPES` (default `bibliotheque-librarian`); its client puts a book in their right hand. `BuildingLayout` adds a `library` room after the office when missing, prefers room shelves for `researching`, and sends a librarian subagent to the Library while it researches and to its parent's pod otherwise.

### Activity Inference (server/agentDetector.ts)

The session file `status` comes first (`combineWithSessionStatus`): `waiting` → `meeting` (label "Waiting for you"), `idle` → `idle`, `busy` with a text-only tail → `planning`. Any other status, or none, uses the transcript alone.

From the transcript, activity is inferred from the **most recent tool_use**, not from user input text (`inferActivityFromTool`):
- Read/Grep/Glob/Agent/WebSearch/WebFetch/Skill/ToolSearch → `researching`
- MCP tools (`mcp__*`) → `researching` when the operation name holds a read word, else `implementing`
- Edit/Write (code files) → `implementing`; Edit/Write (.md/.rst/.txt/README/docs/) → `writing_docs`
- EnterPlanMode/ExitPlanMode/TaskCreate/TaskUpdate → `planning`; AskUserQuestion → `meeting`
- Bash is split into simple commands and classified by program (`inferBashActivity`): test runner → `testing`, commit/push/deploy step → `deploying`, git diff/log/show/blame → `reviewing`, curl/lsof/gdb → `debugging`, only read-only programs → `researching`, else `implementing`
- Last assistant message is text-only → `idle`

The detector reads the session's own `<project-dir>/<sessionId>.jsonl`. Many sessions can share one project directory, so the newest file there may belong to another session. A session without its own transcript shows `idle`. The project directory name is the cwd with every non-alphanumeric character replaced by `-`; older Claude Code versions kept the `.`, so that name is the fallback. Lines are read newest first and joined across 50 KB chunks, up to 4 MB.

### Codex source (server/codexSource.ts)

A built-in source registered in `vitePlugin.ts` with the plugin sources (not as `core`), so a Codex failure drops only Codex agents. It is active only when the Codex home exists (`CODEX_HOME`, else `os.homedir()/.codex`). The `codexHome` option overrides it, and `null` turns it off; tests always pass `null` or a fixture. It walks `sessions/YYYY/MM/DD/rollout-*.jsonl` without following symlinks (realpath containment) and keeps files changed within `RECENT_WINDOW_MS` (10 min), max 50. The first `session_meta` line is canonical: thread `id`, `cwd`, `parent_thread_id` (or `source.subagent.thread_spawn.parent_thread_id`), `subagent_history_start_ordinal`. Activity comes from the newest decisive record in the last 256 KB: shell calls and `CommandExecution` items use the exported `inferBashActivity`; `task_complete`, `turn_aborted` or an assistant message → `idle`. Records before the child history boundary are skipped. Observations use `provider: 'codex'`; the browser appends ` · codex` to the floating label (`StickFigure.setTag`). Presence means "the rollout changed recently", never "the process is alive".

### Subagent Detection

Subagents (spawned via the Agent tool) are detected only from the parent's own `~/.claude/projects/<encoded-cwd>/<sessionId>/subagents/`. Each subagent has a `.meta.json` (with `agentType` and `description`) and its own `.jsonl` transcript. A subagent is considered active if its transcript was modified within the last 30 seconds, or if its newest message is a tool call without a result (up to 10 minutes). Their activity is inferred from their own transcript, independently from the parent session.

### Agent names (server/agentDetector.ts)

`sessionName`: a main session uses the session file `name` when `nameSource` is a string other than `derived` (seen: `auto`; `derived` is an automatic `<folder>-xx` name). Otherwise, or when the name is not 1 to 80 characters after trimming, it uses `path.basename(cwd)`. `subagentName`: the meta `name` (Claude Code writes it for team agents), else `description`, else `agentType`, else `subagent`. The herdr enricher runs later and can still replace a main session name with its tab label. `projectAgents` caps the name at 60 characters.

### Rendering budget (src/scene/FrameLoop.ts)

`FrameLoop` runs the logic at most 30 times a second (`RenderScheduler`) and renders only when something moved: a figure part (`FigureBatch.sync`), the camera, a static batch, the view mode, a selection (the ring pulses), or `sceneChanged()` (after each poll and world update). Without motion it renders once per second. `scene.matrixWorldAutoUpdate` is false: the loop updates world matrices once per tick.

- **Animation sleep** (`src/scene/AnimationSleep.ts`): before each tick the loop puts to sleep the figures out of the camera view or farther than `ANIMATION_DISTANCE` (25). A sleeping figure skips only its continuous sway: `AgentManager.update` keeps a walk going to its arrival snap and turn (`StickFigure.walking`), and when the pose to show changes (`StickFigure.poseKey`: activity, posture, raised hand, and once at creation) it calls `StickFigure.settle`, one update long enough to finish the transition and every eased joint. The figure then holds that pose; its beacon does not bob. With nothing walking and no near figure in view, the office is idle and renders once per second.

- **Static merge** (`src/scene/StaticMerge.ts`): `markStatic(root, { zone, castShadow, overviewLower })` marks furniture that does not move (the hall, each room, each mission room, the hall walls, each lamp in place). `StaticBatch.update` merges its `MeshToonMaterial` meshes into one mesh per material and shadow flags. Sources stay in the graph on `STATIC_SOURCE_LAYER` (31), so names, `visible` and wall rebuilds keep working; a batch rebuilds when a source is added, removed, hidden or takes another material. `getToonMaterial` returns a shared cached material: swap it (a locked mission floor), never recolor it. Not merged: other materials (canvas boards), transparent meshes, and meshes under `userData.dynamic` or `userData.overviewHidden`. Rooms and mission rooms cast no shadow: they lie outside the cone of the three hall lamps. A mark inside a marked root starts its own zone (the walls inside a room).
- **Cutaway** (`src/scene/Cutaway.ts`): a zone marked with `overviewLower: <full height>` carries that height on its container. `applyCutaway(scene, overview)` runs in the loop right after the static merge: in the overview it scales those containers on y down to `overviewHeight` when the mark sets it, else `OVERVIEW_WALL_HEIGHT` (0.5), in first person back to 1, and asks for a render and a shadow redraw when it changed something. A batch rebuilt while lowered builds its geometry at full height. New add-on walls and door frames go in such a zone (never `userData.dynamic`), so the budget holds.
- **Figure batch** (`src/characters/FigureBatch.ts`): parts made in `StickFigureParts.ts` (`userData.figurePart`, shared geometries) draw as one `InstancedMesh` per shape and material. `sync` finds the parts again each tick, so parts attached later join. The BMAD hats are figure parts too: each hat kind is built once and cloned (shared shapes, never disposed). The parts move to `FIGURE_PART_LAYER` (30); `pickAgent` enables it on its ray for one pick and restores the mask. Other meshes attached to a part (GitHub cards, a book) stay on layer 0. Instance matrices are float32: `sync` compares at that precision, so a still figure far from the origin does not count as moved.
- **Shadows**: `shadowMap.autoUpdate = false`. `needsUpdate` is set on a batch rebuild, a view mode change, a figure set change, new shadow casters (`casterSignature`), a WebGL context restore, or a figure that walks or turns inside a shadow light's frustum. A figure that only sways in place there redraws the shadows at most every `IDLE_SHADOW_INTERVAL_MS` (500).
- **Overview and isometric view**: `renderQuality` sets the pixel ratio to at most 1.5 and `BasicShadowMap`; first person keeps 2 and `PCFShadowMap`.
- **Labels**: `renderOnScreenLabels` hides labels outside the screen during the CSS2D pass only.
- **Budget test**: `tests/render-budget.test.ts` builds the office at the real size (`tests/real-size-office.ts`: 25 rooms, 40 agents, 20 with BMAD hats, 10 with GitHub cards) and fails above `DRAW_CALL_BUDGET` (500) from the first-person start pose, the overview and the isometric view (`realSizeCameras`). A sprite counts as one camera call. The 25 room labels draw in one call; the hall wall pieces on hidden sides merge in one `overview-hidden-walls` group that merges in place. `countDrawCalls(scene, camera)` culls like WebGLRenderer: the camera pass keeps meshes in the camera frustum, each shadow map keeps the casters in its light frustum (meshes with `frustumCulled = false`, like the figure batch, count everywhere). Without a camera it counts the worst case. `pnpm measure` prints the numbers; `?debug=1` exposes `window.__officeStats`. The loop resets `renderer.info` before each render (`autoReset = false`), so `lastCalls` counts the shadow pass too and `__officeStats.drawCalls()` (culled from the current camera) can be compared with it.

### Key Patterns

- **Toon shading**: All meshes use `MeshToonMaterial` with a 4-step gradient map, cached in `Materials.ts`
- **Station occupancy**: `Station.occupied` flag prevents multiple agents at one location. On activity change, old station is released before new one is claimed
- **Teleport vs walk**: `addAgent()` teleports to station instantly; `setActivity()` triggers a walk animation (4.5 units/sec) with leg/arm swing
- **Dwell time (activity layout)**: `ActivityLayout` takes `{ dwellMs, now }` (default 0 = move at once). With `dwellMs > 0`, `seatFor` keeps the seat on a station type change and records a pending trip; `update()` returns the `LayoutMove` once the new type lasted `dwellMs`. A change back to the seat type cancels it, a third type restarts the timer, `release` drops it. `registry.ts` reads `?dwell=<seconds>` (`dwellMsFromSearch`, 0 to 30). The figure switches its activity pose at once; the building layout keeps its own dwell
- **Same-type station stickiness**: If an activity change maps to the same station type (e.g. implementing→debugging), the agent stays at its current desk
- **Skeleton animation**: Hierarchical joints (root→body→shoulders/hips→limbs) animated per-activity with sine waves and `approach()` easing
- **Colors**: Centralized palette in `Colors.ts` with 8 accent colors for agents; an agent's color comes from an FNV-1a hash of its ID
- **Triage list (side panel)**: `src/ui/AgentPanel.ts` groups agents into Needs you (attention `waiting`), Your turn (attention `your-turn`), Working (subagents nested under `extras.parentId`), Idle and Cold (any attention in the cold band, always starts collapsed), with count chips on top. Needs you, Your turn and Cold sort by `compareWaits`. Rows are created once per agent and moved or edited in place on each poll; the scroll position, the groups the user opened or closed and a focused menu survive. Your turn starts collapsed above 5 rows, Idle always starts collapsed. A click on a row calls `selectAgent`; the selected row is marked. A click on the Needs you chip itself calls `onTopCount` with `oldestFreshWait(group.agents)` (the fresh agent with the longest wait), when one exists, through `selectOrFly` (below) so it still recenters when that agent is already selected; without a fresh wait the chip only opens the group, as before. The activity menu (P14) appears only with `?demo=1` (`isDemoMode`). `setupPanelCollapse` hides the panel body and stores the choice in localStorage (`agents-office.panel-collapsed`). Until the first `render`, the list shows a `.triage-loading` line. All text goes through `textContent`. Key / (issue #85): `focusFilter()` gives the `.triage-filter` search input the focus; its `input` event stores the lowercased, trimmed text and `applyFilter()` hides a row (`row.card.hidden`) whose name and activity do not contain it, case-insensitively. `render()` calls `applyFilter()` again, so the filter survives a poll. Group counts and chips are not filtered (they still count every member of the group). `expandPanel(root, button, storage)` opens a collapsed panel (the same effect as a click on the collapse button) before main.ts calls `focusFilter()`, so `/` on a collapsed panel is never silently inert. Needs you and Your turn come from `queueBucket` (`src/ui/attention.ts`), the same function key N's queue reads, so the panel's groups and the queue order never diverge.
- **Off-screen marker (src/scene/OffscreenMarker.ts, src/ui/OffscreenMarkers.ts)**: `projectToClip(position, camera)` returns the NDC position, and two flags from the point's view-space position (`matrixWorldInverse`, where the camera looks down its own -Z): `behind`, true only for a perspective camera and only when the point sits on the camera's own side (view-space Z > 0), never for an orthographic camera (the isometric view); and `pastFar`, true when the point is ahead of the camera (view-space Z < 0) but farther than `camera.far`. Neither flag mirrors the arrow; only `behind` does. `offscreenMarker(projection, width, height, margin, avoid?)` is pure: `null` when the point draws inside the frame, else a point on the screen edge and an angle for the arrow, in screen-pixel convention (y down, 0 points right). NDC converts to pixels on each axis against its own half-extent before the edge clamp, so a non-square canvas does not pull the point toward the wrong edge. A point on the camera's own center axis, behind it, has no direction to flip: it gets a default (right) instead of a divide-by-zero. With `avoid` (a `Rect`, for example the side panel's own bounding box in canvas-local pixels), the point clamps into the larger of the two free strips next to it (left/right or above/below `avoid`, whichever has more area), with the ray's own origin at that strip's center — not the canvas center — so a marker still lands outside the panel even on a narrow window where the panel covers the canvas center. `OffscreenMarkers` (DOM controller) computes one candidate point per agent with a fresh wait (`attentionBand(wait) === 'fresh'`) that is off screen, then `clusterBySpacing` iteratively merges any two groups whose *displayed* points collide (not their first members', which is what let two separate, non-overlapping-looking clusters show overlapping markers) into one `button.offscreen-marker-cluster` with a count, keyed by `oldestFreshWait` of the group (the agent it flies to); a group of one stays a plain `button.offscreen-marker` arrow. `refresh(agents)` runs once per frame loop tick (main.ts's `update`, so it costs nothing extra in render terms: `FrameLoop` still renders on demand), reading `camera()` (`ViewController.activeCamera`, so it works in first person, the overview and the isometric view) and `object.getWorldPosition` per agent. A click calls `onSelect(agentId)` (`selectOrFly`, below), which flies the camera there through the normal selection path, even when that agent is already selected. The container (`#offscreen-markers`) sits between the canvas and the side panel in `z-index`; `avoid` (not z-index) is what keeps a marker out from under the panel, since the panel's content would otherwise cover it. A point past the far plane is clipped from the render (so no figure draws there either) but still needs a marker: `pastFar` skips the on-screen check the same way `behind` does, without the flip. Shares `oldestFreshWait` (`src/ui/attention.ts`) with the top-count click above: one helper decides "the fresh wait that has waited longest" for both, and now for a cluster too.
- **Activity text**: every place that shows an activity (panel row, agent card, figure label, bmad label line) uses `activityLabel(agent)` / `activityLabelFor(activity, isSubagent)` from `AgentData.ts`: a subagent (`extras.parentId`) at `idle` reads `DONE_LABEL` ("Done"), everything else reads `ACTIVITY_LABELS`. `AgentManager.addAgent` calls `figure.setSubagent`
- **Legend**: `src/ui/Legend.ts` builds the "?" overlay (`#legend`) from `legendSections(layout, plugins)` each time it opens. An entry with `plugin` shows only while that server plugin is active (`currentWorld().plugins`), an entry with `layout` only in that layout. The band limits come from `ATTENTION_BANDS`. Key `?` (outside form fields) or `#legend-button` toggles it; Esc closes it in the capture phase and stops the event, so the selection stays. Text only, through `textContent`

### Camera

Three modes, owned by `src/scene/ViewController.ts`. The start view: `#view=overview|first-person|iso`, then the last view saved in the browser (`agents-office.view`, `ViewMemory.ts`), then `defaultViewFor(layout)`; main.ts passes it as the `view` option, and the `modeChanged` option saves each change and writes `#view-status` in the panel header (`viewStatusText`). First person: pointer lock + WASD free camera (`FreeCamera.ts`), Shift for speed, no bounding box (only `MIN_EYE_HEIGHT` above the floor), no wall collision. Fly-to in first person: `focusPosition` keeps the camera inside the floor box of the figure's room (`floorUnder(scene, point)`, the smallest `userData.floor` object under the figure), so it never ends behind or inside a wall; too close to the figure, it backs off toward the room center. The ceiling (`userData.ceiling`, marked `dynamic`, so not merged) hides through `applyCeilingCut` in the frame loop when the camera is above `CEILING_HEIGHT` (6 m) or in the overview. Key O switches to the overview (`OverviewCamera.ts`): a fixed angle from above, mouse wheel to zoom, drag or WASD to pan. The overview frames the box from `setOverviewBounds(box)` when a layout sets one, else the union of every object with `userData.floor`, else the fixed room. A layout that adds floor outside the room marks it with `userData.floor` or calls `setOverviewBounds`. Objects with `userData.overviewHidden` (the front and left walls, the ceiling lamps) are hidden while the overview is on. The building walls drop in the overview through cutaway zones (see Rendering budget, Cutaway); the activity layout has none. `#view=overview` starts in the overview. Key I toggles the isometric view (`IsometricCamera.ts`, `#view=iso`, saved as `isometric`) and back to the mode before it; key O from it goes to the overview. It draws through its own `THREE.OrthographicCamera`: `ViewController.activeCamera` returns it in that mode, and main.ts passes `activeCamera` to `FrameLoop` (render, animation sleep, ceiling, label renderer) and `LabelDetailController` (hover raycast); without the option both use `camera` as before. `IsometricController` keeps a floor target and `halfHeight` (the zoom): `frame` fits every corner of `overviewBounds`, the wheel zooms, a drag keeps the floor point under the pointer, a selection eases target and zoom (`IsometricTween`) and pans by the card shift in pixels. `applyTo` puts the camera at `equivalentDistance(fov)` (the overview distance with the same screen size) with a near plane behind it, so `zoomDistance`, the label and sign thresholds, the room label size and animation sleep read the isometric zoom like the overview distance. `isViewFromAbove(mode)` (overview or isometric) drives the cutaway, the ceiling, the near-wall hiding, the render quality and the label rules. Entering or leaving the isometric view cuts (no flight), because the camera changes kind.

### Selection

`src/scene/Selection.ts` holds the shared selection: `selectAgent(id)`, `clearSelection()`, `selectedAgentId()`, `onSelectionChange(cb)` (returns an unsubscribe function). Extensions and other UI (for example a triage list) use it. A click on a figure (raycast against the figure meshes) or on an agent name in the side panel selects; Esc clears, and so does a click that misses every figure (issue #133; a drag release is not that click, and a click while the first-person camera is locked looks around instead); an agent that leaves is deselected. On a new selection the camera flies to the agent in 0.6 s and `SelectionMarker.ts` draws a ring in the agent's color under it. `#focus=<agent id>` selects that agent once it appears. `selectAgent` is a same-id no-op (`SelectionState.select`): clicking an already-selected row does nothing, by design. `selectOrFly(id)` is the one exception: it calls `SelectionState.reselect()` (re-notifies listeners with the current id, unchanged) when `id` is already selected, so `ViewController.selectionChanged` runs again and the camera flies there anyway. The off-screen marker and the top-count chip use `selectOrFly`, since a click there means "take me to this agent" even if it is already the one selected; every other caller keeps plain `selectAgent`.

### Agent card (src/ui/AgentCard.ts)

`AgentCard` subscribes to the shared selection and opens in the same task as the selection: a 360 px `aside#agent-inspector` docked left of `#ui-panel` (top aligned, max height viewport minus 120 px). It shows name, activity, attention line and band (`attentionBand`), provider (Codex or Claude Code), workspace (`extras.group.label`), personas (`extras.badges`), the parent of a subagent, subagents (agents whose `extras.parentId` is this agent; a click selects) and up to `CARD_MAX_ISSUES` (10) of `extras.issues` in API order (newest first), else "No linked issues". `render(agents)` after each poll updates it in place, and a `ResizeObserver` on the panel docks it again when the panel changes size; a new selection swaps the content without hiding the element. Lists are rebuilt only when their content changes. The card knows no plugin: `registerCardAction({ id, label, available, run })` adds a button (run only on click, result as text in the status line), `registerCardPanel({ id, available, render, hide? })` adds a section at the end of the card (a `div.inspector-panel` created once; `render` runs after each selection change and poll while `available`, else the element is hidden and emptied and `hide` runs, as on close), and `registerIssueLinker(fn)` turns an issue into an https link (`plugins/github/links.ts` links only when `issues[].repo` matches the short name of exactly one `owner/name` board from `/api/world`; a number alone never links, it may belong to another repository). `cameraShiftPx()` feeds `ViewController`'s `figureShiftPx` option: on a selection, the camera moves the figure that many pixels left of the canvas center (overview: pans the target; first person: turns only the aim to the screen right; the camera stands where the plain flight puts it, so it never moves sideways into a wall), so it sits in the middle of the free area left of the card. All text goes through `textContent`. Key F (issue #85, fixed under the decision on #85): `pulseFocus()` adds a `.pulse` class to the shown agent's ready action button (today only the herdr focus button) for `PULSE_MS` (1.5 s), a silent no-op without one. It never calls `runAction` and never moves DOM focus onto the button (so Enter cannot then send the request) — S7 keeps a write action behind a click. main.ts pairs it with `ViewController.refocus(agentId)` so F has a visible camera effect too.

### Keyboard triage (src/ui/TriageKeys.ts, main.ts)

Issue #85 adds N, F and / without touching WASD, Space, Q, Shift, O, I, Shift+L, Esc or ?. `handleTriageKey(event, { next, focus, filter })` is a pure dispatcher (one `window` `keydown` listener in main.ts): ignored over a form field (`SELECT`, `INPUT`, `TEXTAREA` or `isContentEditable`) or with Ctrl, Alt or Meta held, else `KeyN` calls `next`, `KeyF` calls `focus`, and `Slash` without Shift calls `preventDefault` (stops the browser's own quick find) then `filter` — Shift+Slash is `?` on a US layout, so the dispatcher leaves it alone and the Legend's own listener opens the legend instead. The same form-field check (now with `isContentEditable`) also guards `FreeCamera.ts`'s own `keydown` listener, `ViewController.ts`'s (O, I, Esc, the overview/isometric WASD pan) and `registry.ts`'s (Shift+L) — the triage filter is the app's first text field, so every global key listener needed the check, not only the new one. main.ts wires `next` to `triageQueue` + `nextInQueue` (`src/ui/attention.ts`) and `selectAgent`; `focus` to `ViewController.refocus(agentId)` (recenter on the current selection, or `selectAgent` the queue head when none) plus `AgentCard.pulseFocus()`; `filter` to `AgentPanel.expandPanel()` (opens a collapsed panel first) then `focusFilter()`.

### Label detail (src/ui/LabelDetail.ts)

`labelDetail(facts, view)` is pure: mode `all` → full; attention `waiting`, selected or hovered → full; overview or isometric view (`isViewFromAbove`) → full when `zoomDistance <= OVERVIEW_FULL_LABEL_ZOOM` (14), else compact; first person → full within `FIRST_PERSON_FULL_LABEL_DISTANCE` (8) of the camera, else compact. `LabelDetailController` recomputes every `LABEL_DETAIL_INTERVAL_MS` (150 ms), on a selection change and after each poll. It only toggles the `compact` class on the label element (`applyLabelDetail`), so the label text, the BMAD persona names and the Codex tag stay as they are; the CSS hides `.activity` and shows a dot from `--agent-color` (set by `StickFigure`). Hover reuses `ViewController.pickAt` at the last pointer position, or the canvas center while the pointer is locked. The zoom comes from `ViewController.zoomDistance`. Key V cycles `smart` → `all` → `smart`; `#labels=all` starts in `all`; `#label-mode` in the side panel header shows the mode. With the `scene` option, the controller also shows or hides detail signs: CSS2D objects with `userData.detailSign = { rect, hoverOnly }` (war room title, lock and past sessions signs, the "You" sign). `signVisible`: mode `all` or pointer over the rect (floor raycast) → shown; `hoverOnly` → hidden otherwise; overview → shown at `zoomDistance <= OVERVIEW_SIGN_ZOOM` (24); first person → within `FIRST_PERSON_SIGN_DISTANCE` (12). It sets `style.visibility`, which CSS2DRenderer does not touch. Room labels (objects with `userData.roomRect`) follow `roomLabelVisible`: hidden in first person while the camera stands in their room, shown otherwise; the controller sets `visible` and calls `userData.applyView({ viewMode, zoomDistance, detail })` only when that changes, then the `changed` option (main.ts asks for a frame).
