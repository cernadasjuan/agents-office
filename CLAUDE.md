## macOS launcher (fork tooling, scripts/launcher/)

`scripts/launcher/agents-office-launcher.mjs` is the entry point a generated `Agents
Office.app` bundle execs (built by `scripts/build-launcher-app.sh`, installed by
`scripts/install-launcher.sh`; see the README's "macOS launcher" section for the command and
what it does). Plain `.mjs`, not `.ts`: the warm-start path has a 1 s budget and skips the tsx
loader. `scripts/launcher/config.mjs` and `detect.mjs` hold the pure, unit-tested logic
(`tests/launcher-config.test.ts`, `tests/launcher-detect.test.ts`); `allowJs` is on in
`tsconfig.json` so `typecheck` still covers the tests that import them. This tooling is outside
`package.json`'s `files`, so it never ships in the published npm package — the mitigation for
bending P6 (no daemon) in this fork only.

`detect.mjs`'s `probeOffice` GETs the office root `/`, not `/api/agents` (that endpoint can
take over 400 ms under herdr enrichment, which could misread a live, slow office as down). It
returns `{ reachable, isOffice }`: `isOffice` is true only when the answer carries this
office's own `index.html` markers (`isOfficeHtml`, the `<title>` and the `#ui-panel` id), so a
different app already holding the port never gets treated as a warm start. The launcher spawns
`vite` only when `reachable` is false; a reachable-but-not-office answer logs it and shows a
macOS notification (`osascript -e 'display notification ...'`) instead of opening a browser or
a second server. `readConfigEnv` requires the config file to be a plain regular file
(`lstatSync`, so a symlink is rejected too) under `CONFIG_MAX_BYTES` (64 KB); anything else
reads as no overrides rather than stalling the launcher. `build-launcher-app.sh` never writes
the repo path into the generated shell source: it `printf`s it to
`Contents/Resources/repo-root.txt` and the generated script (now a fully quoted heredoc, the
same bytes for any `repo_root`) reads it back with `cat` into a quoted variable at run time —
`tests/launcher-build.test.ts` builds the app with a repo root holding a space, a quote and a
`$` and asserts the path reaches disk unchanged and the payload never runs. `find_node` in the
generated script also resolves an nvm default alias (one level of indirection, then the
highest installed version by `sort -V`) before falling back to the first match.

The app icon (issue #205): `scripts/launcher/icon.svg` (a procedurally drawn office/building
motif, plain shapes in the app's own palette, no downloaded brand assets) is packed once into
`scripts/launcher/AgentsOffice.icns` by the maintenance tool `scripts/launcher/generate-icon.mjs`
(Playwright screenshots the SVG at every size `iconutil`'s `.iconset` format wants, then
`iconutil -c icns` packs them; needs the `playwright` dev dependency and its Chromium
download — not a new runtime dependency, and never invoked by an install). Both the `.svg` and
the generated `.icns` are committed; `build-launcher-app.sh` only `cp`s the committed `.icns`
into `Contents/Resources/` and adds `CFBundleIconFile` to `Info.plist` when it finds the file —
a checkout missing it (should not happen) still builds the app, just without an icon
(graceful degradation, `tests/launcher-build.test.ts`).

## Architecture

3D office visualization (Three.js + Vite) that shows running Claude Code agents as animated stick figures. Each agent's activity is detected from real session data and mapped to a physical station in the office.

### Data Flow

```
~/.claude/sessions/*.json → server/agentDetector.ts → GET /api/agents → AgentPoller (3s) → AgentManager → 3D Scene
```

1. **Server** (`server/`): Vite middleware plugin reads Claude session files, validates PIDs, infers activity from transcript `.jsonl` tool_use blocks (language-agnostic), and detects active subagents
2. **Polling** (`AgentPoller.ts`): Fetches `/api/agents` every 3 s, one request at a time with a 5 s limit, and reconciles with AgentManager (add/remove/update). If the API fails (network error, HTTP error, bad JSON), the current scene stays and the failure counts in `pollHealth` (`{ loaded, lastSuccessAt, failures }`); the third `start` argument gets it after every finished poll (a poll skipped while one runs reports nothing). The first good answer always calls `onUpdate`, also for an empty office, so the panel loading text goes. `src/ui/freshness.ts` turns the health into the panel footer (`#panel-footer`): "Loading agents…", "Updated N s ago", amber with "retrying" from `FRESHNESS.warnAfterFailures` (2), red "Server not reachable" from `downAfterFailures` (5). `FreshnessFooter` ticks once a second and only changes text, so it requests no frame. Subagents get a `>> ` prefix in their name
3. **Agent Management** (`AgentManager.ts`): Creates StickFigures and handles their lifecycle. Where a figure goes is the layout's decision (`src/layout/`): `LayoutStrategy.seatFor(agent, previousActivity)` returns a `Seat` (position, look-at, optional forced posture) or null to stay. `ActivityLayout` is the original behavior. `registry.ts` picks the layout from `?layout=`, then browser storage, then the default; Shift+L (`isLayoutSwitchKey`) then a `window.confirm` (`confirmLayoutSwitch`) cycles layouts, one L alone does nothing. `registerLayout(id, factory, { makeDefault, defaultView })`: `defaultViewFor(id)` is the view a layout opens in (first person unless it says otherwise; the building asks for the overview). Optional fork add-ons in `src/addons/*.ts` register more layouts
4. **Scene** (`Office.ts`): 28 stations across 7 types (the 6 lounge sofa seats are seated idle seats) (implementing, planning, researching, testing, reviewing, idle, meeting). One agent per station. When no station of the right type is free, AgentManager opens an overflow spot on open floor; it never uses a station of another type

### Extension seam (server/seam.ts)

Detection runs as a pipeline: the core `claudeSource` (wraps `detectAgents`), then plugin sources, then enrichers in order, then world providers for rooms and boards. A failing or slow plugin step (2 s limit) drops only its own output; a core failure is a 500. `projectAgents` and `projectWorld` are the only exit: they copy whitelisted, cleaned fields and hash every key with the per-run HMAC. `/api/world` uses the same request checks as `/api/agents`. Plugins live in `plugins/<name>/index.ts` (default export `OfficePlugin`) and load through `server.ssrLoadModule` from `AGENTS_OFFICE_PLUGINS=a,b` or `agents-office --plugin a`. Their browser parts live in `plugins/<name>/client.ts` and register an `OfficeExtension` (`src/extensions.ts`) with `plugin: '<name>'`, so they run only while the server plugin is active.

Plugins in this fork: `plugins/bmad/` (persona hats). Its enricher reads the tool_use blocks of `internal.transcriptPath` incrementally (a per-file offset cache) and `internal.agentType`, and sets persona ids as `badges`. `client.ts` stacks one toon hat per badge on `figure.joints.head` (max 4, then a `+N` marker) and adds the persona names to the label activity line. `roster.ts` is the shared persona list. `pnpm dev:fork` loads the fork plugins.

`plugins/skills/` (issue #166, server enricher only, `pnpm dev:fork`): reads the same `internal.transcriptPath` incrementally (its own per-file offset cache) for `Skill` tool_use blocks and sets `display.skills` to every distinct `input.skill` seen this session, newest-loaded last, capped at 8. `server/seam.ts` whitelists it into `projectAgents` as `skills` (same token shape as a badge, `SKILL`, capped at 8 again on the way out). The card's "Persona / Skills" row (`AgentCard.ts`) shows badges then skills; without this plugin loaded, `extras.skills` is undefined and the row falls back to personas only.

- **`plugins/github/`**: opt-in with `AGENTS_OFFICE_GITHUB_REPOS=owner/name[,owner/name]`, else it adds nothing. `gh.ts` runs `gh issue list` via `execFile` (5 s, no shell, 60 s cache) and derives the columns. `transcript.ts` finds issue numbers in Bash tool calls. `client.ts` draws wall boards (`KANBAN_BOARD_SLOTS`). `cards.ts` (`IssueCardBatch`) draws the issue cards as badges: slots near shoulder, far shoulder, then the upper arms (near, far, near); "near" is the side that faces the camera, with a margin so it does not flip in front views. All cards of all agents are one world-space geometry with one canvas atlas (one draw call, no shadow, no raycast). The batch chains `scene.onBeforeRender`, which gets the camera after the world matrices update and before the renderer uploads the geometry: each card is placed from its upper arm joint, kept upright (world up) and turned about the vertical axis to the camera. Cards on one side never overlap (they stack down, or up along a raised arm). Each card has a front and a back quad with their own UVs (no mirrored text). A card reads `<repo>#N`; `repo` is the short name the projection keeps only as a plain token (`repoShortName` in `server/seam.ts`), and the plugin sets it only for a configured repository that holds the issue or that the call named. The border is `color`, a label color the projection keeps only as `rrggbb` (`hexColor`); `gh.ts` picks a `wayfinder:*` label, else the first label. `labelIds.ts` adds one `.github-issues` line (textContent, at most 5 IDs, cut on whole IDs) to each floating label on every `agentsChanged`, because the core rewrites the label on a change; a style element from the plugin keeps the line in compact labels. The enricher refreshes the issue cache itself (bounded at 1.5 s, under the 2 s seam step limit), so `/api/agents` has titles and colors without a `/api/world` call first. `pnpm dev:fork` loads the fork plugins.

`plugins/herdr/` (enricher, `pnpm dev:fork`, plus the opt-in focus write action below): reads only the three `HERDR_*_ID` variables from one batched `ps eww` for new session PIDs, then `herdr tab list` and `herdr workspace list` (cached 10 s, `execFile`, 1.5 s timeout); sets a main session name to its tab label and the workspace as group for the session and its subagents; any failure changes nothing. The command runner is injectable for tests.

- **`plugins/jira/`** (issue #145, personal Jira board): opt-in with `AGENTS_OFFICE_PLUGINS=jira`, needs `AGENTS_OFFICE_JIRA_BASE_URL`/`_EMAIL`/`_TOKEN` (`resolveJiraCredentials` in `jira.ts`), else a local JSON file at `AGENTS_OFFICE_JIRA_CREDENTIALS_FILE`, else `~/.config/agents-office/jira.json`, stat-checked (a regular file, capped at 4 KB) before it is ever read, not just after; without all three it adds no world provider and calls fetch zero times, the same as `github` without a repository. Not in `pnpm dev:fork`: unlike a repo name, the three Jira variables are secrets, so the fork's default command never activates a plugin that reaches an external site on their mere presence in the environment. The base URL must be `https://`, except a loopback host (a local mock Jira for development; the same carve-out S1 gives this office's own server). `fetchJiraTickets` calls `GET <baseUrl>/rest/api/3/search/jql` (the current endpoint; Atlassian removed `/rest/api/3/search`) with the fixed JQL `sprint in openSprints() AND assignee = currentUser()`, Basic auth, an 8 s timeout per page, following `nextPageToken` up to `MAX_PAGES` (3) or 50 results, whichever comes first; a non-OK response (for example the 410 the old path now answers), an unexpected shape, or a network failure all return undefined with one `console.debug` note (never a credential) and no partial page kept. `JiraCache.refresh` caches the combined list for `CACHE_MS` (2 minutes); a failure keeps the last good ticket list, the same cache shape as `IssueCache` in `gh.ts`. `parseJiraSearchPage` shape-checks one page and builds each ticket's `url` as `${baseUrl}/browse/${key}` server-side. `server/seam.ts`'s `jiraTicket` whitelist (`JIRA_KEY`, the same key shape `plugins/peek/transcript.ts` already links) drops a malformed key or a ticket with no status, caps `summary` (80), `status` (32), `priority` (16) and `assignee` (40), and strips `url` unless it is `https`, so a loopback-mock link never reaches the browser. `client.ts`'s `JiraOfficeExtension` (`plugin: 'jira'`) mounts a plain canvas board (`drawJiraBoard`, like the GitHub kanban boards, not a clickable list — see the design note in the pull request) on a side wall of the office room (`scene.getObjectByName('room-0-office')`; absent in another layout or with no data, no board), at a position computed once from the office's own slot and `RoomFrame.point` math (`RoomPlanner.ts` ring 0 index 0), so the plugin needs no runtime import of the building layout. Each row draws the key, then the summary truncated to fit its own column, then the status, priority and assignee in a fixed column of their own that never truncates, so a long summary cannot push the status off the board.

### Read views and the peek plugin (plugins/peek)

`OfficePlugin.views` offers per-agent read views from the closed enum `VIEW_NAMES` (`server/seam.ts`, today only `peek`). `vitePlugin.ts` always mounts `GET /api/views/<name>?agent=<public id>`: `admit` (same checks as every GET route, POST gets 405), then 404 for a view no loaded plugin offers, 400 for an ID that is not 64 hex, 404 for an agent not in the last `/api/agents` answer (the same server-side public id map as write actions), 500 without details when the view throws. The answer goes through `projectPeek` only: at most 10 lines of 200 characters, masked again with `maskedLine` (`server/secrets.ts`: collapse white space and control characters, 4000-character raw cut, `maskSecrets`, then `cutBeforePlaceholder`, which never splits a placeholder), an optional pinned `question`, up to 10 https assets (no credentials in the URL), skills and repos as plain tokens. View data never enters `projectAgents` or `projectWorld`.

`plugins/peek/` (opt-in, on in `pnpm dev:fork`; breaks S4 by design, see the README): `transcript.ts` (`PeekReader`) reads `internal.transcriptPath` (`.jsonl`, regular file only): the last 2 MB the first time, then only new bytes (4 MB cap per read, else it starts again at the tail; lines over 1 MB are skipped). It keeps per file the last 10 entries (assistant text through `maskedLine`; tool calls as `toolSummary`: the tool name plus a safe token such as the Bash program and subcommand, a file base name, a skill or subagent type, a WebFetch host), assets from tool inputs only (GitHub issue and PR URLs, `gh issue|pr <verb> N -R owner/repo`, GitLab `/-/merge_requests/N` URLs, Jira keys whose prefix is in `AGENTS_OFFICE_PEEK_JIRA`, default `DEFAULT_JIRA_SITES`), skills from Skill calls and repos from Edit/Write/NotebookEdit paths and git write commands (`-C <dir>` or the session cwd), mapped to the git root's short name (a worktree `.git` file maps to its main repository). `question` is the newest entry when it is assistant text and the agent has an attention. `client.ts` registers a card panel (`PeekPanel`): on only while `/api/world` lists `peek`. It loads on selection, then every `PEEK_REFRESH_MS` (5 s) by its own timer while the card shows the agent; a render inside the throttle schedules one trailing load. `hide()` (the card calls it on close or when the panel is not available) stops the timer. A late answer for another agent is dropped, all text goes through textContent, links only for https. `setPeekTextHidden` hides all peek sections (the hook for the private mode, #91).

### Write actions (server/actions.ts)

S7 keeps the API read-only by default. A write action exists only when a loaded plugin offers it in `OfficePlugin.actions` behind its own opt-in. Today there is one: `focus` from `plugins/herdr/` with `AGENTS_OFFICE_HERDR_FOCUS=1`. Without an offered action, `vitePlugin.ts` mounts no POST route, serves no token and adds no header. Rules for every write action:

- The action name is in the closed enum `ACTION_NAMES` (`server/seam.ts`). The route is `POST /api/actions/<name>`, the body exactly `{ "agent": "<public id>" }` (`parseActionBody`). Never a raw ID, a path, text or a command from the browser.
- `admit(..., 'POST')`: loopback, local Host, `Origin` required and equal to the server origin, `Sec-Fetch-Site` same-origin when present. Then `WriteActions.handle`: `X-Agents-Office-Token` (random 32 bytes per server start, from `GET /api/actions/token`, SHA-256 then `timingSafeEqual`) → 403, `Content-Type: application/json` → 415, 10 per minute → 429, body over 1 KB → 413, bad shape → 400, unknown agent or agent without the action → 404.
- The public id resolves to the observation from the last `/api/agents` answer (a server-side map). The agent must advertise the action in `display.actions`. `projectAgents` copies `actions` only for names in `ACTION_NAMES` that the server enabled.
- `OfficeAction.run(observation)` re-checks its target right before it acts and returns `done` (200), `gone` (409) or `failed` (502). Subprocess only through `execFile` with fixed argv, a strict ID pattern and a timeout.
- One audit line per attempt (`time`, `action`, public `agent`, `result`) to `AGENTS_OFFICE_AUDIT_LOG` or `os.tmpdir()/agents-office-audit.jsonl`, mode 0600. Never the token, a raw ID or the body.
- With an action on, every response gets `X-Frame-Options: DENY` and `frame-ancestors 'none'`.
- Tests inject the command runner and the audit path (`auditLogPath` option). Never run a real write command in a test.

herdr focus: the enricher keeps `focusTargets` (observation id → pid, pane id, tab id; a subagent uses its parent's pane) and sets `display.actions = ['focus']`. `run` re-reads `ps eww` for the pid and `herdr pane get <pane>` (same pane and tab), then `herdr agent focus <pane>`, else `herdr tab focus <tab>` when the pane has no detected agent or agent focus fails. `plugins/herdr/client.ts` registers a "Focus in herdr" button in the agent card (`registerCardAction`) for agents whose `extras.actions` holds `focus`; `FocusClient` fetches the token (once more after a 403), and the card shows the result as text. `pnpm dev:fork` sets `AGENTS_OFFICE_HERDR_FOCUS=1`; the request still goes out only on the click.

### Attention (server/attention.ts, src/ui/attention.ts)

A built-in enricher sets `attention` for main sessions: status `waiting` → `waiting` (blocked), `idle` → `your-turn`, with `waitMinutes` from `statusUpdatedAt`. The browser puts each wait in an age band (`attentionBand`, thresholds in the one constant `ATTENTION_BANDS`: fresh under 15 min, aging under 24 h, cold from 24 h). `callsForYou` (fresh) drives the raised right hand (the arm overrides the activity pose; the rest stays) and the amber beacon, for both attentions. `queuesForYou` (fresh or aging) drives the building queue, `countsInTab` (fresh) the tab title (`tabTitleFor`), `compareWaits` the order (fresh before aging, the longest wait first). Without `waitMinutes` each helper keeps the old behavior: beacon and queue for `waiting` only, tab count for both. The agent card, the panel row and the floating label all show the same text for the same agent at the same time: "Waiting for you · N min" or "Your turn · N min" (`attentionLine`), never each surface's own raw activity text (issue #168 — before this, the card and the panel showed the raw activity, for example "Taking a break", while only the label already overrode it). `orchestrating` (issue #168) is set only alongside `your-turn`, for a session with a subagent of its own still running (`detectSubagents` only ever reports an active one, so "any observation with this agent as its `parentId`" already means "running now"); `callsForYou` never fires for it, and `StickFigure` stands it with hands on hips (`animateActivity`'s `orchestrating` param, `ActivityAnimations.ts`) instead of the raised hand — it finished its own turn, but it is not blocked on you. The beacon's meaning is reachable without opening the legend (issue #170): `BEACON_HINT` is the one hint string. The agent card shows it on its own line whenever the selected agent's beacon is on (the always-reachable surface — review fix: a figure label has `pointer-events: none`, so a `title` attribute there never shows). `LabelDetailController`'s `onHoverHint` option reuses the same hover detection it already runs for label declutter to also report `BEACON_HINT` and the cursor position for the hovered agent, when its beacon is on; `main.ts` owns a small DOM tooltip (`.beacon-tooltip`, fixed position, `pointer-events: none`) that follows it. Neither path fires in first person with the pointer locked (no mouse to hover with); the card line still works there. `AgentPoller.ts`'s `EXTRA_KEYS` carries `orchestrating` to the client (review fix: the third time a seam field shipped without it, after `skills`); `tests/poller.test.ts` guards this by comparing against a real `projectAgents` call with every field set. Key N's queue (issue #85): `triageQueue` filters to `queuesForYou` and sorts by `compareWaits`, the same set and order as the panel's needs-you/your-turn groups; `nextInQueue(queue, currentId)` steps to the agent after `currentId`, cycling back to the first past the end, and returns the first agent when `currentId` is null or has left the queue (a cold start, or a selection moved to cold or cleared).

### Stuck (server/stuck.ts, src/ui/attention.ts)

`stuckEnricher` (built in, run after `attentionEnricher`) marks `display.stuck` for a main session (`parentId` unset) whose status is `busy` and whose own transcript (`internal.transcriptPath`) has no write for `STUCK_AFTER_MINUTES` (60, the one constant next to `ATTENTION_BANDS` in `src/ui/attention.ts`). It reads the file's mtime, not the session's `statusUpdatedAt`, so a long tool call with a recent write never qualifies. Stateless like every enricher (P12): each poll recomputes it from the file, so a session that writes again loses the mark on the next poll with no extra state. `stuck` is a plain boolean in the `DisplayExtras`/`AgentExtras` whitelist (`server/seam.ts` `projectAgents`, `src/agents/AgentPoller.ts` `EXTRA_KEYS`). `activityLabel` (`src/agents/AgentData.ts`) and `attentionLine` (`src/ui/attention.ts`) show `STUCK_LABEL` ("Stuck?") in its place, in the panel row and the floating label; a wait (`attention`) still takes priority, since a waiting or idle session is never `busy`. `labelDetail` (`src/ui/LabelDetail.ts`) treats a stuck agent like a fresh wait: `LabelFacts.stuck` forces a full label, the same as `blockedRecently`, `selected` or `hovered`, so the mark shows in the default smart mode even far from the camera and unselected (otherwise the compact label hides `.activity`, the element the mark writes into).

### Fork add-on: building layout (src/addons/building*)

`src/addons/building.ts` registers `BuildingLayout` as the default layout (fork only, tier T3). `RoomPlanner.ts` is pure geometry: 12x12 room slots around the 30x26 hall (first ring of 7, the office first at east-center; later rings shift outward and open toward the inner room), door gaps and wall pieces. `rooms.ts` builds a room in a local frame (`RoomFrame`: depth from the door wall, position along it): floor marked `userData.floor`, walls named `room-walls` as tall as the main room (`WALL_HEIGHT`, now `OFFICE.height`, issue #176: no more separate, shorter room constant), a ceiling (`buildCeiling`, `userData.ceiling`, in the shared `room-ceilings` static zone), a `door-frame` group (two `door-post` meshes and a `door-lintel` in the floor color, `doorFrame`), a room label (`roomLabel` in `roomLabels.ts`: a handle object named `room-label` at the room center whose position and scale are the plate pose, text in `userData.roomLabel`, room in `userData.roomRect`; `RoomLabelBatch` (`roomLabelBatchFor(scene)`, one per scene, `BuildingLayout` collects each new room) draws every handle as one instanced billboard quad with a canvas atlas, a slot per label redrawn when the face changes, scale 0 for a hidden or detached handle; a full face (2 lines of 16) and a compact face of 2 condensed lines of 7 (`compactLabelLines`: a longer name keeps its first line and its last word), `roomLabelLines` with " · " as a line break; `userData.applyView` takes the view from the label controller and sets the face and `roomLabelPose`: first person a 0.7 m plate centered at 2.2 m with depth test, overview a plate that grows with `zoomDistance / 40`, capped at `ROOM_LABEL_MAX_WIDTH` and 5 m, drawn on top, compact face unless zoomed in, pointed at or labels: all), furniture and stations from the room plan (see Furniture library below). `markCutaway` puts the walls (and a mission room's closed door) in the `room-walls` static zone with `overviewLower: WALL_HEIGHT`; `markDoorCutaway` puts the door frames in the `door-frames` zone, which drops to `OVERVIEW_DOOR_HEIGHT` (1.2) instead; the hall walls use the `hall-walls` zone with `overviewLower: OFFICE.height`. `roomTitle(kind, earlierKinds)` names a room: lounges and waiting rooms are numbered (`Lounge N`, `Waiting room N`). `BuildingLayout.ts` keeps per-agent state (home desk, current seat, target, pending trip, queue time): desk work at home, trips to station types after `dwellMs` (4 s), main sessions that `queuesForYou` (or with activity `meeting` and no cold wait) go to `queue` spots at once and are reordered by `compareWaits` in `update()`; a cold wait leaves after the dwell time, subagents use pod spots around the parent desk. An exhausted station type adds a room (`ROOM_STATION_TYPE`), saved in `localStorage` (`agents-office.building.rooms`) and rebuilt on load. The hall side walls are hidden and replaced by `building-hall-walls` with a door per first-ring room.

### Furniture library (src/furniture/index.ts, src/addons/building/furnishing.ts)

Code builds every piece; nothing is loaded from a file. Each piece is a factory in `src/furniture/` (one file per piece or family: `Armchair.ts`, `Tables.ts` with the low table and the credenza, `DisplayShelf.ts`, `FloorLamp.ts`, `Portrait.ts`, `Decorations.ts` with plants, rug, wall art and clock). `PIECES` in `src/furniture/index.ts` lists them all: `PIECES.<name>(args)` returns a `PieceSpec` (`name`, `category`: `station`, `furniture` or `plant`, `create`). A piece faces +z, stands on y = 0 and uses toon materials only (the static merge takes it; the portrait sprite is the one exception). Reuse palette colors that a room already has (`Colors`, the book colors): a new color in the `rooms` zone costs one draw call.

`roomFurnishing(kind, { doorAlong, usersOffice })` in `furnishing.ts` is the one plan per room kind: `pieces` (piece, `a`, `d`, optional `y` for wall pieces, `turn` added to the face-the-door rotation), `spots` (stations: type, position, look-at, posture) and `signs` (the office "You" sign and the queue count). Plans hold positions only; `rooms.ts` builds no furniture geometry and imports no factory: `furnish()` creates each piece (named in `userData.piece`), each spot as a station and each sign. Rules a plan keeps (tested in `tests/furnishing.test.ts`): no standing piece within `QUEUE_SPOT_RADIUS` (0.35 m) of a spot, none in the hall door path (`doorAlong` +/- 1.2 m, depth 0 to 2.5 m) or in the far wall gap an outer room's door may open (a = +/- 1.2 m, last metre). Every room kind keeps that far wall gap clear, checked at every real door position; the library's far-wall shelves sit off-center (or off the wall) to leave it open. The office lounge corner goes to the front corner away from the door (mirrored when `doorAlong < 0`); the office plan is tested at every real door position (0, 1, 2.5, -2.5). Only your office (room 0, `usersOffice`) gets the portrait and the count sign; a second waiting room gets neither. The office queue: 23 spots in five rows 1.3 m apart, 2.3 m between spots, odd rows shifted by 1.15 m. Each row fills mirrored pairs center-out, nearest pair first, the exact center last, so a small queue stands symmetric; a row fills completely before the next opens.

### Floors (issue #118, step one of three)

A session's floor is a repo, not a herdr workspace (the issue #119/#123 comment: "the floor of a session must come from its repo, not from the herdr workspace tag"): `server/floor.ts`'s built-in `floorEnricher` resolves every observation's `internal.cwd` to the floor name of the git repository that holds it (`FloorResolver`, a worktree maps to its main repository, the same rule `plugins/peek/transcript.ts`'s `repoOf` uses, duplicated rather than imported since a core enricher must not depend on an opt-in plugin), bounded at 40 directories up and cached per directory for the server's run. A relative `cwd`, a directory with no repository, or an unreadable or malformed worktree `.git` file (review round 1: none of these fall back to naming the directory itself) resolves to `GENERAL_FLOOR` ('general'), never left unset — a subagent shares its parent's `internal.cwd`, so it always lands on the same floor with no special case. A worktree `.git` file's `gitdir` pointer is resolved against the worktree's own directory when it is itself relative (review round 1), before the main repository's path is extracted. `qualifiedFloorName` (revised, issue #191: a floor name should read the way Gabriel actually expects it, not a filesystem accident) first tries the repo's own `origin` remote, read straight from `.git/config` (`remoteOwnerRepo`, a plain text scan, never a shell-out — `server/floor.ts` is core, not an opt-in plugin, and the no-shell rule applies everywhere here, not only inside a plugin), through `FloorResolver`'s own `cachedRemoteOwnerRepo` (keyed by repo root, not by `cwd`: several sessions, and several directories inside one of them, share one root, and must not each re-read the same config file): a GitHub URL (`https://github.com/owner/repo[.git]` or `git@github.com:owner/repo.git`) or a GitLab URL with any subgroup depth both reduce to the last path segment before the repo name, then the repo name (`owner/repo`, the last subgroup and the repo for GitLab). Only without a remote, or with one that does not parse, does it fall back to the earlier rule (review round 1, blocking: two repos that share a leaf folder name under different organizations, for example two separate `project-management` checkouts, must resolve to two different floors): the repo's own directory name, qualified by its immediate parent directory's name when that parent exists and fits the whitelist too (`org/repo`); otherwise the bare repo name alone. `server/seam.ts`'s `projectAgents` re-validates the value through its own `floorName` whitelist (one segment, or two joined by a single slash; never the `repoShortName` function an issue card's `repo` uses, which keeps only the text after the *last* slash and would silently destroy the org qualifier) before it ever becomes the public `floor` field: defense in depth, never trusting an enricher's own output blindly.

`src/floors/FloorRegistry.ts` is the pure client data model (no scene, no DOM): `isFloorName` (the same one-or-two-segment shape), `knownFloors` (every floor a set of agents names, general always included), `defaultFloor` (`#floor=` in the URL, then the last floor stored in `localStorage` under `FOCUSED_FLOOR_KEY`, else `ALL_FLOORS`), and `reloadForFloorSwitch`. `ALL_FLOORS` ('all', review round 2, blocking) is the default on a fresh page load and whenever nothing else is chosen: no filter, every agent shows, the exact pre-floors behavior — a fresh page load has not polled any agent yet, so there is nothing to pick a specific floor's room list from before the first poll answers, and the one place meant to catch every waiting agent must never silently narrow to one repo by default. Because of this, there is no migration: `ALL_FLOORS` maps to no `floor` option on `BuildingLayout` at all (`src/addons/building.ts` normalizes it to `undefined`), so it keeps using the exact legacy bare storage key the single building always used — the room list a user already grew keeps existing, under the same key, with no copy and no second key to keep in sync. `reloadForFloorSwitch` (review round 2, blocking: the previous version only called `location.reload()` on the branch the select's own change handler never reaches, since re-selecting the already-focused floor is a no-op there; picking an actually different floor went through `location.assign()` with only the URL fragment changed, which updates the address bar but never reloads the document) now always reloads: it updates the `#floor=<name>` hash through `assign()` first when it differs, then reloads unconditionally — the same "the page reloads" pattern `reloadForLayoutSwitch` (`src/layout/registry.ts`) already uses for Shift+L, rather than a live teardown-and-rebuild of the scene graph mid-session, which would risk the render budget and the static-merge zones (`tests/render-budget.test.ts`'s pinned worst case is unaffected by this PR). `src/floors/floorState.ts` holds the one floor this page load is focused on (`main.ts` sets it, once, before `createLayout` runs `src/addons/building.ts`'s factory, which reads it, normalizing `ALL_FLOORS` away, to construct `BuildingLayout` with `{ floor }`).

`BuildingLayout`'s `floorStorageKey(floor)` namespaces `BUILDING_STORAGE_KEY` as `BUILDING_STORAGE_KEY:<floor>`; without a `floor` option (every test from before floors shipped, and `ALL_FLOORS` at runtime) it stays the bare legacy key — a feature appears only when its data exists (rule 3), so none of the existing `tests/building.test.ts` cases needed to change. `AgentPoller`'s optional third constructor argument, `focusFloor`, filters `reconcile`'s own agent list to one floor (an agent with no `floor` field is treated as general, never dropped); unset (every layout that is not floor-aware, today `activity`, and `main.ts`'s own normalized `ALL_FLOORS` case), every agent shows, the old behavior. `start`'s fourth argument, `onAgents`, still receives the raw, unfiltered poll answer, so the floor-switch menu (`src/ui/FloorSwitch.ts`, a plain `<select>` in the panel header, `#floor-switch-container` in `index.html`, `ALL_FLOORS` always listed first) can list every floor with a tracked session, not only the focused one.

Step one gave the office a floor to stand on. Gabriel's one personal office in a lobby layer above the floors with a cross-floor waiting queue (#192) is step three: see "The lobby and the cross-floor waiting queue" below.

### Floors, step two: missions, kanban and the legacy-room migration (issue #191)

A mission war room and a GitHub kanban board each carry their own `repo` tag on `RoomInput`/`BoardInput` (`server/seam.ts`), `WorldRoom`/`WorldBoard` (`src/extensions.ts`): a full `owner/repo` pair when the source actually knows the owner (a GitHub issue ref, a configured kanban repo — `repoTag` in `server/seam.ts` keeps it whole, through the existing `ownerRepo` whitelist, rather than `repoShortName`, which would silently drop the owner half), else a bare repo short name. `src/floors/FloorRegistry.ts`'s `matchesFloor` does the actual matching, the same shape a floor name itself can carry (`owner/repo` when its own git remote resolved one, bare otherwise, below): with an owner on both sides it compares the pair exactly (two repos that share a leaf name under different owners must never match on name alone); with an owner on only one side, or neither, it falls back to `floorRepo`'s own trailing-segment compare. A room or board with no resolvable repo at all carries no tag, and shows on `ALL_FLOORS` only — it is never guessed onto whichever floor happens to be focused.

`plugins/missions/index.ts`'s `missionRepo` resolves a mission's own repo in order, kept whole throughout: its `root_issue`'s own `owner/repo`, else its first GitHub member's, else — with neither — the mission's own root directory's floor (`server/floor.ts`'s `FloorResolver`, the same rule a session's cwd uses, so it may itself resolve to `owner/repo` when that directory's own remote does), absent entirely (review, blocking: not `GENERAL_FLOOR`) when that root resolves to no repo at all — `'general'` is itself a selectable floor, so tagging an unresolved mission with it would wrongly pull every such mission in the moment a user actually focuses general; an unresolved repo shows on `ALL_FLOORS` only, same as a room or board with no tag at all. `plugins/github/index.ts` tags each repo's own board with the full `owner/repo` its configuration already names (one board per configured repo already) — never the issue card's own `shortName`, which is a different, intentionally-bare tag for a different surface. `BuildingLayout.syncWorldRooms` filters incoming world rooms by `matchesFloor` before building anything, when `this.floor` is set (`ALL_FLOORS` — `this.floor` unset — keeps building every room, unchanged); `plugins/github/client.ts`'s `worldChanged` does the same for kanban boards, reading `focusedFloor()` directly since a plugin's own client extension has no constructor option for it — `focusedFloor()` itself defaults to `ALL_FLOORS` (review, blocking: not `GENERAL_FLOOR`), since the activity layout and any other floor-unaware layout never call `setFocusedFloor` at all, and a default of a real, selectable floor would make this same filter hide every board with no floor ever chosen.

**Migration:** today's single building's room list (the legacy bare `BUILDING_STORAGE_KEY`) becomes the first specific floor a user ever focuses (`BuildingLayout.migrateLegacyRooms`, a one-time marker key, not a dual-read path), so none of a user's already-grown rooms are lost once floors exist. `ALL_FLOORS` never migrates; a floor that already has its own room list is never overwritten; the legacy key itself is read but never deleted. The remote-naming revision above can still rename a floor a user already focused or grew rooms on (`projects/agents-office` to `gabriel-amyot/agents-office`, for example); there is no migration from the old `floorStorageKey` to the new one, since the client never sees a repo's raw directory path and so cannot recompute what the old name would have been (S4) — a renamed floor's grown rooms (beyond office and library) regrow from scratch under the new name, the same cold-start a floor gets the first time it is ever focused.

**A quiet floor never forces you off it (review, revised):** the floor-switch menu (`src/ui/FloorSwitch.ts`) lists every floor with a tracked session right now, plus the focused one, plus every floor with its own stored room list (`src/floors/FloorRegistry.ts`'s `floorsWithStoredRooms`, reading the real `BUILDING_STORAGE_KEY:<floor>` keys present, not a separate registry) — a floor with zero live agents, renamed or simply idle, still renders its own quiet building from its own stored rooms, and stays reachable from this menu so you can always leave it yourself. An earlier revision instead force-reloaded a stale-looking floor back to `ALL_FLOORS`; dropped, since a client-side snapshot of "who is active right now" cannot reliably tell a quiet-but-valid floor apart from a permanently renamed one, and guessing wrong took the choice away from the user instead of just leaving it to them.

**Deferred from #191:** the library root (AC1, folding #119) needs a real documentation-index convention to read from first — this repo's own `docs/` is three flat files, no `INDEX.md` — and Prospero's #119 comment calls for building from each section's own `INDEX.md` specifically, to mark an archived page as archived rather than showing it as current; guessing a convention here risked contradicting that spec once written. The corridor (#123) shipped separately: see "The growing mission corridor" below.

### The growing mission corridor (issue #123)

Before this, only a war room's first row opened directly onto the hall; every row after it chained onto the room in front of it through `extraDoors` (the same mechanism `RoomPlanner`'s rented-room rings still use), so a deep room was reachable only by crossing another room's closed door. Fixed by running a dedicated mission corridor (`missionRooms.ts`'s `missionCorridorRect`) up the old shared boundary between the two wing columns (x = -9) and giving every row's room a door straight onto it, on the column's own outward-facing side wall (`east`/`west`, never `north`/`south` into the room before or after it). The corridor opens into the hall once, at its own fixed south end (`MISSION_CORRIDOR_DOOR`/`MISSION_CORRIDOR_HALL_DOOR`), and its own rect grows one `ROOM_SIZE` further north every time a new row is rented (`BuildingLayout.rebuildMissionCorridor`) — there is no room-count cap on the wing it serves (decision record D3, SBE-19). `MissionRoom` no longer carries its own `extraDoors`: every war room's walls build from its one door alone, so `wallColliders()` and the corridor's own walls are the only two places that ever need rebuilding when a room is added, never another room's walls. The corridor's floor, walls and ceiling merge into the same `missions`/`room-walls` static zones a single war room already used (`StaticMerge`), so growing the wing costs the renderer close to nothing beyond each room's own 4 canvas wall boards (not a toon material, never merged) — measured at 42 war rooms well under the draw-call budget (`tests/mission-corridor-render-budget.test.ts`). ### Activity Inference (server/agentDetector.ts)

The session file `status` comes first (`combineWithSessionStatus`): `waiting` → `meeting` (label "In a meeting", issue #169 — not "Waiting for you": that wording belongs to the attention system, for a different reason, and still overrides this label through `attentionLine` whenever attention is actually set), `idle` → `idle`, `busy` with a text-only tail → `planning`. Any other status, or none, uses the transcript alone.

From the transcript, activity is inferred from the **most recent tool_use**, not from user input text (`inferActivityFromTool`):
- Read/Grep/Glob/Agent/WebSearch/WebFetch/Skill/ToolSearch → `researching`
- MCP tools (`mcp__*`) → `researching` when the operation name holds a read word, else `implementing`
- Edit/Write (code files) → `implementing`; Edit/Write (.md/.rst/.txt/README/docs/) → `writing_docs`
- EnterPlanMode/ExitPlanMode/TaskCreate/TaskUpdate → `planning`; AskUserQuestion → `meeting`
- Bash is split into simple commands and classified by program (`inferBashActivity`): test runner → `testing`, commit/push/deploy step → `deploying`, git diff/log/show/blame → `reviewing`, curl/lsof/gdb → `debugging`, only read-only programs → `researching`, else `implementing`
- Last assistant message is text-only → `idle`

The detector reads the session's own `<project-dir>/<sessionId>.jsonl`. Many sessions can share one project directory, so the newest file there may belong to another session. A session without its own transcript shows `idle`. The project directory name is the cwd with every non-alphanumeric character replaced by `-`; older Claude Code versions kept the `.`, so that name is the fallback. Lines are read newest first and joined across 50 KB chunks, up to 4 MB.

### Codex source (server/codexSource.ts)

A built-in source registered in `vitePlugin.ts` with the plugin sources (not as `core`), so a Codex failure drops only Codex agents. It is active only when the Codex home exists (`CODEX_HOME`, else `os.homedir()/.codex`). The `codexHome` option overrides it, and `null` turns it off; tests always pass `null` or a fixture. It walks `sessions/YYYY/MM/DD/rollout-*.jsonl` without following symlinks (realpath containment) and keeps files changed within `RECENT_WINDOW_MS` (10 min), max 50. The first `session_meta` line is canonical: thread `id`, `cwd`, `parent_thread_id` (or `source.subagent.thread_spawn.parent_thread_id`), `subagent_history_start_ordinal`. Activity comes from the newest decisive record in the last 256 KB: shell calls and `CommandExecution` items use the exported `inferBashActivity`; `task_complete`, `turn_aborted` or an assistant message → `idle`. Records before the child history boundary are skipped. Observations use `provider: 'codex'`; the browser appends ` · codex` to the floating label (`StickFigure.setTag`). Presence means "the rollout changed recently", never "the process is alive".

### Subagent Detection

Subagents (spawned via the Agent tool) are detected only from the parent's own `~/.claude/projects/<encoded-cwd>/<sessionId>/subagents/`. Each subagent has a `.meta.json` (with `agentType` and `description`) and its own `.jsonl` transcript. A subagent is considered active if its transcript was modified within the last 30 seconds, or if its newest message is a tool call without a result (up to 10 minutes). Their activity is inferred from their own transcript, independently from the parent session.

### Agent names (server/agentDetector.ts)

`sessionName`: a main session uses the session file `name` when `nameSource` is a string other than `derived` (seen: `auto`; `derived` is an automatic `<folder>-xx` name). Otherwise, or when the name is not 1 to 80 characters after trimming, it uses `path.basename(cwd)`. `subagentName`: the meta `name` (Claude Code writes it for team agents), else `description`, else `agentType`, else `subagent`. The herdr enricher runs later and can still replace a main session name with its tab label. `projectAgents` caps the name at 60 characters.

### Rendering budget (src/scene/FrameLoop.ts)

`FrameLoop` runs the logic at most 30 times a second (`RenderScheduler`) and renders only when something moved: a figure part (`FigureBatch.sync`), the camera, a static batch, the view mode, a selection (the ring pulses), or `sceneChanged()` (after each poll and world update). Without motion it renders once per second. `scene.matrixWorldAutoUpdate` is false: the loop updates world matrices once per tick.

- **Animation sleep** (`src/scene/AnimationSleep.ts`): before each tick the loop puts to sleep the figures out of the camera view or farther than `ANIMATION_DISTANCE` (25). A sleeping figure skips its steady-state animation update: `AgentManager.update` keeps a walk going to its arrival snap and turn (`StickFigure.walking`), and when the pose to show changes (`StickFigure.poseKey`: activity, posture, raised hand, hands on hips, and once at creation) it calls `StickFigure.settle`, one update long enough to finish the transition and every eased joint. The figure then holds that pose; its beacon does not bob. No pose has a continuous sway (#163: idle, testing, debugging, deploying and meeting all held a small `Math.sin` wobble on the body or neck, removed; Gabriel found a crowd of swaying agents odd, and the sway kept `FigureBatch.sync` reporting every awake figure as moved on every frame, which kept `FrameLoop`'s `active` flag true and defeated the once-a-second idle render even for a figure right in front of the camera). A beacon's bob (a fresh or stuck wait) is the one pose-independent continuous motion left; animation sleep still skips it the same way for a sleeping figure. With nothing walking, no beacon bobbing, and no awake figure's pose still easing toward its target, the office is idle and renders once per second, near figures included — a figure mid-clip (below) being the one exception, same as a walk.

- **Occasional idle clips** (`src/agents/ActivityAnimations.ts`'s `occasionalVariant`, issue #164): the sway #163 removed left idle, testing and planning fully static once settled; Gabriel asked for the occasional NPC-style clip instead, so a figure still reads as "doing something," not frozen. Each activity's clip pool (idle: a stretch, a phone check, a look around; testing: praying for the tests; planning: sketching on a notepad instead of the whiteboard) is scheduled per figure by `occasionalVariant`, keyed by the figure's own skeleton root (`j.root.uuid`) through a deterministic FNV-1a hash — no shared `Math.random`, so a crowd of figures never starts the same clip at the same instant, and a test gets the same sequence every run for one uuid. A figure draws a random gap (`minGap`-`maxGap` seconds) before its next clip, plays it for `duration` seconds (plus a short natural ease-back, not counted in `duration`), then draws the next gap; `clipCount > 1` never repeats the clip it just played. Idle's gap (45-90s, duration 1.6s) keeps the office-wide cadence close to "one figure every several seconds" for a dozen idle agents, measured at 25-35 renders per 3 s averaged over a long run versus about 3 per 3 s with no clip active and about 188 per 3 s under the old continuous sway (`tests/idle-render-rate.test.ts`). A sleeping figure (`AnimationSleep`) never advances a clip's clock: `AgentManager.update` only calls `settle` once per pose-key change for a sleeping figure, so its clip schedule effectively pauses, consistent with "a sleeping figure does nothing extra." A raised hand or hands-on-hips suppresses the clip scheduler outright (`animateActivity` passes `suppressVariant = raiseHand || orchestrating` down to `animateIdle`/`animateTesting`/`animatePlanning`, review fix): either override already owns an arm a clip would also reach for, so the clip's own clock simply waits rather than drawing a clip the override's save/restore of its own joints would not catch. The clip also owns every joint it drives for the frames it plays — the base pose and the clip no longer both write the same joint every frame (review fix: they used to, and the two targets fought, so the stretch clip settled around half its real angle instead of reaching it).

The same `animateIdle` runs for a seated idle figure and an overflow one standing with no free idle seat: there is no separate "standing with nothing to do" look in the *flat office* layout (`ActivityLayout`), so an idle agent beyond its 8 idle-type seats (2 at the coffee machine, 6 on the sofas) still reads as "taking a break," clips included. `ActivityLayout.freeStationKey` already prefers a true idle-type seat over an overflow spot when one is free; that overflow case is a capacity fact of a busy office with many finished subagents (each counted `idle`, `AgentData.ts`'s `DONE_LABEL` case), not a seat-assignment bug.

Point 3 of #164's real standing cause lives in the *other* layout, `BuildingLayout` (`src/addons/building/BuildingLayout.ts`), not `ActivityLayout`: every subagent whose parent already holds a desk or a room seat routes to `target: 'pod'` (`targetFor`), and `podKeys()` built each of a parent's 6 pod slots with `posture: 'standing'`, for any activity, by design — a pod subagent stood whether idle or busy, which read as "something is wrong" once idle lost its continuous sway (#163). The fix: `podKeys()` now builds a small stool (`src/furniture/Stool.ts`, registered in the furniture library as `PIECES.stool`) at each pod slot, added to the scene under a shared `pods` static-merge zone (so any number of pods across any number of parents still costs the draw-call budget only 1-2 merged meshes, one per stool material), and sets `posture: 'seated'` instead — the same `postureOverride` mechanism a sofa's idle seat already uses. A pod subagent now sits, whatever its activity.

- **Static merge** (`src/scene/StaticMerge.ts`): `markStatic(root, { zone, castShadow, overviewLower })` marks furniture that does not move (the hall, each room, each mission room, the hall walls, each lamp in place). `StaticBatch.update` merges its `MeshToonMaterial` meshes into one mesh per material and shadow flags. Sources stay in the graph on `STATIC_SOURCE_LAYER` (31), so names, `visible` and wall rebuilds keep working; a batch rebuilds when a source is added, removed, hidden or takes another material. `getToonMaterial` returns a shared cached material: swap it (a locked mission floor), never recolor it. Not merged: other materials (canvas boards), transparent meshes, and meshes under `userData.dynamic` or `userData.overviewHidden`. Rooms and mission rooms cast no shadow: they lie outside the cone of the three hall lamps. A mark inside a marked root starts its own zone (the walls inside a room).
- **Cutaway** (`src/scene/Cutaway.ts`): a zone marked with `overviewLower: <full height>` carries that height on its container. `applyCutaway(scene, overview)` runs in the loop right after the static merge: in the overview it scales those containers on y down to `overviewHeight` when the mark sets it, else `OVERVIEW_WALL_HEIGHT` (0.5), in first person back to 1, and asks for a render and a shadow redraw when it changed something. A batch rebuilt while lowered builds its geometry at full height. New add-on walls and door frames go in such a zone (never `userData.dynamic`), so the budget holds.
- **Figure batch** (`src/characters/FigureBatch.ts`): parts made in `StickFigureParts.ts` (`userData.figurePart`, shared geometries) draw as one `InstancedMesh` per shape and material. `sync` finds the parts again each tick, so parts attached later join. The BMAD hats are figure parts too: each hat kind is built once and cloned (shared shapes, never disposed). A hat mesh never sets `castShadow` (`plugins/bmad/hats.ts`, #96, #98): a bucket's `castShadow` is `parts.some((part) => part.castShadow)`, so a bare hat bucket never joins the shadow pass, dropping dozens of tiny casters (one per persona hat shape and color) that a toy-sized shadow would not show anyway. The parts move to `FIGURE_PART_LAYER` (30); `pickAgent` enables it on its ray for one pick and restores the mask. Other meshes attached to a part (GitHub cards, a book) stay on layer 0. Instance matrices are float32: `sync` compares at that precision, so a still figure far from the origin does not count as moved. A part may also carry `userData.tint` (a `THREE.Color` multiplier, issue #125 part 3): every bucket's `InstancedMesh.instanceColor` holds it (white, a no-op multiply, by default), so a part that needs more color variety than its one shared material — a mission's hand color — costs no extra bucket or draw call.

Without a camera it counts the worst case (200 GitHub cards on 40 agents: 364, was 466). `pnpm measure` prints the numbers; `?debug=1` exposes `window.__officeStats`. ### Key Patterns

- **Toon shading**: All meshes use `MeshToonMaterial` with a 4-step gradient map, cached in `Materials.ts`
- **Station occupancy**: `Station.occupied` flag prevents multiple agents at one location. On activity change, old station is released before new one is claimed
- **Teleport vs walk**: `addAgent()` teleports to station instantly; `setActivity()` triggers a walk animation (4.5 units/sec) with leg/arm swing
- **Dwell time (activity layout)**: `ActivityLayout` takes `{ dwellMs, now }` (default 0 = move at once). With `dwellMs > 0`, `seatFor` keeps the seat on a station type change and records a pending trip; `update()` returns the `LayoutMove` once the new type lasted `dwellMs`. A change back to the seat type cancels it, a third type restarts the timer, `release` drops it. `registry.ts` reads `?dwell=<seconds>` (`dwellMsFromSearch`, 0 to 30). The figure switches its activity pose at once; the building layout keeps its own dwell
- **Same-type station stickiness**: If an activity change maps to the same station type (e.g. implementing→debugging), the agent stays at its current desk
- **Skeleton animation**: Hierarchical joints (root→body→shoulders/hips→limbs) animated per-activity with sine waves and `approach()` easing
- **Colors**: Centralized palette in `Colors.ts` with 8 accent colors for agents; an agent's color comes from an FNV-1a hash of its ID
- **Triage list (side panel)**: `src/ui/AgentPanel.ts` groups agents into Needs you (attention `waiting`), Your turn (attention `your-turn`), Working (subagents nested under `extras.parentId`), Idle and Cold (any attention in the cold band, always starts collapsed), with count chips on top. Needs you, Your turn and Cold sort by `compareWaits`. Rows are created once per agent and moved or edited in place on each poll; the scroll position, the groups the user opened or closed and a focused menu survive. Your turn starts collapsed above 5 rows, Idle always starts collapsed. A click on a row calls `selectAgent`; the selected row is marked. A click on the Needs you chip itself calls `onTopCount` with `oldestFreshWait(group.agents)` (the fresh agent with the longest wait), when one exists, through `selectOrFly` (below) so it still recenters when that agent is already selected; without a fresh wait the chip only opens the group, as before. The activity menu (P14) appears only with `?demo=1` (`isDemoMode`). `setupPanelCollapse` hides the panel body and stores the choice in localStorage (`agents-office.panel-collapsed`). Until the first `render`, the list shows a `.triage-loading` line. All text goes through `textContent`. Key / (issue #85): `focusFilter()` gives the `.triage-filter` search input the focus; its `input` event stores the lowercased, trimmed text and `applyFilter()` hides a row (`row.card.hidden`) whose name and activity do not contain it, case-insensitively. `render()` calls `applyFilter()` again, so the filter survives a poll. Group counts and chips are not filtered (they still count every member of the group). `expandPanel(root, button, storage)` opens a collapsed panel (the same effect as a click on the collapse button) before main.ts calls `focusFilter()`, so `/` on a collapsed panel is never silently inert. Needs you and Your turn come from `queueBucket` (`src/ui/attention.ts`), the same function key N's queue reads, so the panel's groups and the queue order never diverge.
- **Off-screen marker (src/scene/OffscreenMarker.ts, src/ui/OffscreenMarkers.ts)**: `projectToClip(position, camera)` returns the NDC position, and two flags from the point's view-space position (`matrixWorldInverse`, where the camera looks down its own -Z): `behind`, true only for a perspective camera and only when the point sits on the camera's own side (view-space Z > 0), never for an orthographic camera (the isometric view); and `pastFar`, true when the point is ahead of the camera (view-space Z < 0) but farther than `camera.far`. Neither flag mirrors the arrow; only `behind` does. `offscreenMarker(projection, width, height, margin, avoid?)` is pure: `null` when the point draws inside the frame, else a point on the screen edge and an angle for the arrow, in screen-pixel convention (y down, 0 points right). NDC converts to pixels on each axis against its own half-extent before the edge clamp, so a non-square canvas does not pull the point toward the wrong edge. A point on the camera's own center axis, behind it, has no direction to flip: it gets a default (right) instead of a divide-by-zero. With `avoid` (a `Rect`, for example the side panel's own bounding box in canvas-local pixels), the point clamps into the larger of the two free strips next to it (left/right or above/below `avoid`, whichever has more area), with the ray's own origin at that strip's center — not the canvas center — so a marker still lands outside the panel even on a narrow window where the panel covers the canvas center. `OffscreenMarkers` (DOM controller) computes one candidate point per agent with a fresh wait (`attentionBand(wait) === 'fresh'`) that is off screen, then `clusterBySpacing` iteratively merges any two groups whose *displayed* points collide (not their first members', which is what let two separate, non-overlapping-looking clusters show overlapping markers) into one `button.offscreen-marker-cluster` with a count, keyed by `oldestFreshWait` of the group (the agent it flies to); a group of one stays a plain `button.offscreen-marker` arrow. `refresh(agents)` runs once per frame loop tick (main.ts's `update`, so it costs nothing extra in render terms: `FrameLoop` still renders on demand), reading `camera()` (`ViewController.activeCamera`, so it works in first person, the overview and the isometric view) and `object.getWorldPosition` per agent. A click calls `onSelect(agentId)` (`selectOrFly`, below), which flies the camera there through the normal selection path, even when that agent is already selected. The container (`#offscreen-markers`) sits between the canvas and the side panel in `z-index`; `avoid` (not z-index) is what keeps a marker out from under the panel, since the panel's content would otherwise cover it. A point past the far plane is clipped from the render (so no figure draws there either) but still needs a marker: `pastFar` skips the on-screen check the same way `behind` does, without the flip. Shares `oldestFreshWait` (`src/ui/attention.ts`) with the top-count click above: one helper decides "the fresh wait that has waited longest" for both, and now for a cluster too.
- **Activity text**: every place that shows an activity (panel row, agent card, figure label, bmad label line) uses `activityLabel(agent)` / `activityLabelFor(activity, isSubagent)` from `AgentData.ts`: a subagent (`extras.parentId`) at `idle` reads `DONE_LABEL` ("Done"), everything else reads `ACTIVITY_LABELS`. `AgentManager.addAgent` calls `figure.setSubagent`
- **Legend**: `src/ui/Legend.ts` builds the "?" overlay (`#legend`) from `legendSections(layout, plugins)` each time it opens. An entry with `plugin` shows only while that server plugin is active (`currentWorld().plugins`), an entry with `layout` only in that layout. The band limits come from `ATTENTION_BANDS`. Key `?` (outside form fields) or `#legend-button` toggles it; Esc closes it in the capture phase and stops the event, so the selection stays. Text only, through `textContent`

### Camera

Three modes, owned by `src/scene/ViewController.ts` (#173 dropped the overview mode and key O; `OverviewCamera.ts` stays only for the shared pose math — `CameraPose`, `PoseTween`, `floorUnder`, `overviewBounds` — that first person, the isometric view and the desk view all still use). The start view: `#view=first-person|iso|desk`, then the last view saved in the browser (`agents-office.view`, `ViewMemory.ts`), then `defaultViewFor(layout)` (the building layout's default is `isometric`); main.ts passes it as the `view` option, and the `modeChanged` option saves each change and writes `#view-status` in the panel header (`viewStatusText`). An unknown or retired view name in the hash is `null` to `viewModeFromName`, so `chooseViewMode` treats it exactly like a missing hash: it tries the last saved view next, then the layout default (#173 review: `#view=overview`, the retired mode's own name, actually lands in isometric for the building layout, not first person, since isometric is that layout's default). `#zoom=<distance>` (issue #89, `parseViewHash` in `Selection.ts`) starts the view at that camera distance instead of its own default framing: `ViewController.applyStartZoom` runs once, right after the constructor enters the start view, and converts the distance to the isometric `halfHeight` (`distance * tan(fov/2)`, the inverse of `equivalentDistance`), clamped into the view's own pan/zoom limits, the same clamp a wheel tick already respects. A no-op in first person, which has no zoom. `#room=<name>` (issue #89) frames a named room instead of `#zoom=` or the view's own default framing, from the active layout's optional `roomView(name)` (`LayoutStrategy.ts`; only `BuildingLayout` implements it, keyed by room kind — "office" always the first one, "Your office", never a later overflow waiting room — or by a mission id, `mission:<slug>` or the bare slug). `ViewController.applyStartRoom` flies the isometric view to the room's bounds with the same pure framing math (`framedHalfHeight`) a selection flight target would use, never touching the view's own pan/zoom limits the way `frame`/`updateBounds` would; first person stands at the room's `standing` pose. `BuildingLayout.roomView` (and the pure `roomViewFromSlot`) compute the room's world bounds and a standing point a third of the way in from the door, facing further inward, straight from `RoomPlanner`'s `Rect`/`RoomFrame`, with no scene traversal. First person: pointer lock + WASD free camera (`FreeCamera.ts`). Issue #174 replaced the old flight (Space/Q fly up/down, Shift a 2.5x speed multiplier, movement along the full look direction including pitch) with ground-walk: movement projects `forward`/`right` onto the ground plane, ignoring pitch, so looking up or down never tilts the walk. Eye height (`EYE_HEIGHT`, from `FIGURE_EYE_HEIGHT` in `StickFigureParts.ts`, the same neck-plus-head height the stick figure itself uses) is fixed while grounded; a jump (`JUMP_SPEED`, Space, once per press, `grounded` guards the second one mid-air) moves it only while airborne, landing it back at the eye height for whichever pose is held (`CROUCH_EYE_HEIGHT` while Shift is down). The jump arc (review, #185) is the closed-form parabola of `jumpElapsed` (seconds since takeoff) against `jumpLaunchHeight` (the eye height it launched from), not velocity integrated frame by frame: a pure function of elapsed time has no step size to depend on, so the apex matches at any frame rate. Landing requires both falling (the parabola's own velocity term at or below zero) and at or below the live target height, so a posture change mid-air (standing up while still rising) can change where gravity pulls toward without falsely ending the jump. Double-tapping W within `DOUBLE_TAP_RUN_MS` sets `running` until W is released; Shift crouches and slows instead of speeding up (`CROUCH_SPEED_MULTIPLIER`). Wall collision (issue #194): `FreeCamera.setWallColliders(walls)` holds a flat list of `WallRect`s (`minX`/`maxX`/`minZ`/`maxZ`), fed every frame by `ViewController`'s `wallColliders` option (`LayoutStrategy.wallColliders()`; only `BuildingLayout` implements it, from `rooms.ts`'s `wallRects` — the same `rect`/`doors` pairs that build the real wall meshes, with doors already left out as gaps, so the collision list can never drift from what actually draws). Movement resolves one axis at a time against that list (`moveWithCollision`): a wall blocking one axis never blocks the other, so walking into a wall at an angle slides along it instead of sticking. A layout with none set (or a test) keeps the old, unobstructed walk — graceful degradation, no physics engine, no per-frame scene raycast. `setMovementEnabled(false)` turns ground-walk off without touching look; the desk view (#161, below) is the one caller. `currentEyeHeight()` exposes the live standing-or-crouched target so a first-person flight (`flyToAgent` below) can land exactly there, instead of a fixed height that would pop to it a frame later. Fly-to in first person: `focusPosition` keeps the camera inside the floor box of the figure's room (`floorUnder(scene, point)`, the smallest `userData.floor` object under the figure), so it never ends behind or inside a wall; too close to the figure, it backs off toward the room center. The ceiling shows in first person and hides only in the isometric view (`userData.ceiling`, `applyCeilingCut` in the frame loop; issue #176 dropped the old height-based rule, since first person no longer flies above wall height once it walks on the ground, #174). The main room's ceiling (`Walls.ts`) is marked `dynamic`, so not merged, since there is only one; every other room's ceiling (`buildCeiling` in `rooms.ts`, used by `buildRoom` and the war rooms in `missionRooms.ts`) shares one merged `room-ceilings` zone with no shadows, so the room count does not grow the draw-call budget. Key I toggles the isometric view (`IsometricCamera.ts`, `#view=iso`, saved as `isometric`) and back to first person. It draws through its own `THREE.OrthographicCamera`: `ViewController.activeCamera` returns it in that mode, and main.ts passes `activeCamera` to `FrameLoop` (render, animation sleep, ceiling, label renderer) and `LabelDetailController` (hover raycast); without the option both use `camera` as before. **One goal pose, one damped follower (issue #113 redesign).** `IsometricController` (`ViewController`'s private `isometric` field) holds the view's goal: a floor `target` and `halfHeight` (the zoom), plus the pan/zoom limits (`bounds`, `minHalfHeight`, `maxHalfHeight`). Every input edits only this goal and nothing else: `zoom` (the wheel), `zoomTowardCursor` (cursor-anchored zoom, issue #87), `drag`/`pan` (a drag, WASD), `focusOn` (a selection flight) and `retrack` (issue #113: a room added or removed, or a resize — re-derives the limits for the new bounds/aspect, re-clamping the goal only if it now falls outside them). `ViewController`'s private `liveIsometric` field is the only thing that ever reaches the camera; `update()` calls the pure `followIsometric(live, goal, delta, rates)` every frame, which moves `live` toward the goal by a step capped to a fixed speed (world units/second for pan, a fraction of `halfHeight`/second for zoom), frame-rate independent, landing exactly on the goal once within one step — there is no tween object, no elapsed time, no start pose to go stale, so retargeting the goal again before the follower arrives (another wheel tick, a second room removed) just gives it a new place to keep closing on, never a jump. `rates` is the one knob a goal edit sets, not a tween (PR #200 review round): `ViewController`'s private `isometricFollowRates` field holds whichever of `DIRECT_FOLLOW_RATES` or `FLIGHT_FOLLOW_RATES` the most recent goal edit chose, read fresh by `update()` every frame. Direct manipulation (the wheel, `zoomTowardCursor`, a drag, WASD) sets `DIRECT_FOLLOW_RATES` right before it edits the goal, so the live pose stays responsive even mid-flight. A flight-type change (`flyToAgent` — a selection, `refocus`/F, an off-screen marker click — and the `#zoom=`/`#room=` start parameters) sets `FLIGHT_FOLLOW_RATES`, about 6x slower, so it still reads as a flight (about 0.5-0.7 s at a typical office distance) instead of a jump. Only the camera-kind change itself (a fresh entry into the view, via `frame`) stays a cut: `liveIsometric` is set to the goal's own state at once, with nothing left for the follower to chase; a `#zoom=`/`#room=` start parameter is a flight FROM that fresh framing, not a further cut. `applyIsometricState` puts the camera at `distanceForHalfHeight(live.halfHeight, fov)` with a near plane behind it; its far plane covers `Math.max(liveDistance, goalDistance)`, so a correction in either direction never clips the building while live and goal briefly disagree. `zoomDistance` and the label/sign/animation-sleep thresholds all read the GOAL's own `equivalentDistance`, not the live, lagging pose — they react to where the camera is headed, the same instant a wheel tick or a selection sets it. `ViewController.sceneChanged()` (main.ts calls it after every agent poll and world poll) and a `resize` listener both just flag the limits dirty; the actual bounds box (`overviewBounds`) only recomputes once, lazily, in the next isometric `update()` tick — never every frame, and never when nothing changed. Objects with `userData.hiddenFromAbove` (the front and left walls, the ceiling lamps) are hidden in the isometric view; the building walls drop there through cutaway zones (see Rendering budget, Cutaway); the activity layout has none. `isViewFromAbove(mode)` (true only for the isometric view now) drives the cutaway, the ceiling, the near-wall hiding, the render quality and the label rules. Entering or leaving the isometric view cuts (no flight), because the camera changes kind.

**Desk view (issue #161):** a third `ViewMode`, `'desk'`. `BuildingLayout.deskView()` returns the camera pose (pure, from `RoomFrame.point` on `OFFICE_DESK`, the same office-room assumption `rooms.ts`'s own room naming and the jira wall board already make): behind the desk (`OFFICE_DESK.d + DESK_SEAT_OFFSET`), a little lower than `roomView`'s standing pose (`DESK_EYE_HEIGHT`, below `FIGURE_EYE_HEIGHT`), looking back toward the queue (`OFFICE_DESK.d - DESK_LOOK_OFFSET`), plus its own vertical FOV (`DESK_CAMERA_FOV`, issue #199: wider than the first-person default, 60° in `SceneSetup.ts`, and `DESK_SEAT_OFFSET` pulled back from 1.0 to 2.0 — together the minimum that keeps the nearest queue row's outer pair, `a = ±4.6`, inside the frustum at every supported aspect ratio; `deskGeometry.ts`'s own comments on both constants have the exact numbers and why neither alone, at a room-safe offset, is enough). `ViewController.setMode('desk', animate)` flies there like any other first-person-shaped pose (`CameraPose`, `PoseTween`); it is a no-op without a pose (`options.deskView` missing or null — rule 3, graceful degradation: a layout with no rooms never shows a desk). Entering desk mode also widens the shared `camera`'s own FOV to `deskPose.fov` when the layout supplies one (`ViewController.deskRestoreFov` saves the prior value), and restores it on the way out — first person and the isometric view (a separate orthographic camera) never see the wider lens; a `deskView` without `fov` (an older layout, or a test fixture) keeps the old behavior untouched. `isViewFromAbove('desk')` is false (desk reads like first person: full walls, full ceiling, full render quality), but `setMode` still force-exits pointer lock entering it, and `setPointerLockFilter`'s installed callback already requires `currentMode === 'first-person'`, so desk mode can never re-engage it from any click. `update()` never calls `updateFreeCamera` in desk mode — that function always re-applies the module-level mouse-look quaternion even with `setMovementEnabled(false)`, so desk bypasses it outright and re-applies its own fixed pose every frame instead. `selectionChanged`/`refocus` (keys click/F) still show the card and the selection ring, they just skip the camera-fly call while `currentMode === 'desk'` — the camera itself never moves (the walk-to-the-front nice-to-have, issue #162, is a separate, conditional follow-up that was not built in this round). Idle default: `ViewController` tracks `idleSeconds` (reset by `markActive()`, wired into every pointer/keyboard/wheel listener in `listen()`, plus a pointer-locked mousemove); past `idleTimeoutSeconds` (`DEFAULT_IDLE_TIMEOUT_SECONDS`, 120, overridable for tests) from any other mode, `update()` calls `setMode('desk', true)` itself, the same no-op-without-a-pose rule applying. Key `H` (`toggleDesk`) jumps to desk, or back to the saved first-person pose, the same `savedFirstPerson` restore key `I` already uses — `N` keeps meaning "next in queue", the two keys never collide. Two small monitors (`src/addons/building/deskMonitors.ts`, `DeskMonitorsExtension`, a core fork add-on registered from `src/addons/building.ts`, not a plugin) sit on the desk: a canvas-texture frame-plus-face each, the same cheap pattern as the jira wall board, never merged into the static batch. The left one mirrors the triage panel's waiting list (`triageQueue`, always mounted once the office room is in the scene); the right one mirrors the jira plugin's board (`world.jiraTickets`) and only mounts while there is data (graceful degradation, the same rule the wall board itself follows) — together they cost at most 4 draw calls, the waiting one alone at most 2 (`tests/desk-monitors.test.ts` pins this).

**Double-click a room in isometric (issue #175):** `ViewController`'s canvas `dblclick` listener, gated to `currentMode === 'isometric'` only. `roomUnderPoint` raycasts the active (orthographic) camera against a `y=0` ground plane (`GROUND_PLANE`), then calls `options.roomAt?.(x, z)` — `BuildingLayout.roomAt`, a pure rect-containment scan over every building room (`slotFor(record.index).rect`) and mission room (`room.slot.rect`); null between rooms, or without the option at all. A hit calls `setMode('first-person', false, room.standing)`: the third, optional `explicitPose` parameter overrides the generic "restore `savedFirstPerson`" target only for this one call, landing at the room's own standing pose instead (the same pose `#room=`/`applyStartRoom` already computes). Leaving isometric always cuts (the existing `fly` formula), never flies, matching every other isometric exit.

**Zoom toward the cursor (issue #87):** `ViewController`'s wheel handler no longer calls `zoom()` directly. It turns the pointer position into NDC and calls `zoomTowardCursor` (`IsometricCamera.ts`; #173/#184 review dropped `OverviewCamera.ts`'s own copy along with the rest of `OverviewController`, dead once the overview mode shipped out): a pure function that reads the floor point (y = 0) under the cursor through `floorPointUnderCursor` before the zoom, applies the existing clamped `zoom()`, reads the floor point again, then shifts `target` by the difference through `shiftTarget` (the same x/z clamp as `pan`). This is exact, not an approximation: the isometric camera keeps a fixed forward/right/up axis set as `halfHeight` changes, so a `target` shift of `(dx, 0, dz)` moves the floor intersection by exactly `(dx, 0, dz)` too (the camera position shifts by the same amount; the ray direction never changes). `floorPointUnderCursor` and `zoomTowardCursor` take no camera object and no scene, so `tests/isometric-view.test.ts` checks the projected NDC directly, with no DOM, canvas or render.

### Selection

`src/scene/Selection.ts` holds the shared selection: `selectAgent(id)`, `clearSelection()`, `selectedAgentId()`, `onSelectionChange(cb)` (returns an unsubscribe function). Extensions and other UI (for example a triage list) use it. A click on a figure (raycast against the figure meshes) or on an agent name in the side panel selects; Esc clears, and so does a click that misses every figure (issue #133; a drag release is not that click); an agent that leaves is deselected. On a new selection the camera flies to the agent in 0.6 s and `SelectionMarker.ts` draws a ring in the agent's color under it. `#select=<agent id>` (`#focus=`, its older name, still works) selects that agent once it appears. `selectAgent` is a same-id no-op (`SelectionState.select`): clicking an already-selected row does nothing, by design. `selectOrFly(id)` is the one exception: it calls `SelectionState.reselect()` (re-notifies listeners with the current id, unchanged) when `id` is already selected, so `ViewController.selectionChanged` runs again and the camera flies there anyway. The off-screen marker and the top-count chip use `selectOrFly`, since a click there means "take me to this agent" even if it is already the one selected; every other caller keeps plain `selectAgent`.

**A locked click selects under the center dot, not the cursor (issue #205).** First person's own click listener (below, `ViewController.listen`) used to treat a click while the pointer is locked as "look around" only (issue #133). It still does that, but a left click now also picks: since the OS-hidden cursor sits pinned to the canvas center under lock, `pickAtCenter()` reads the same raycast `pickAt` does, from the canvas's own center point instead of the click's screen position — the dot and the pick are always the same spot. A hit selects (never leaves pointer lock, never presses Esc); a miss is the old behavior exactly, it only looks around, it never clears the open card (deliberate: looking past an already-selected agent to aim a run is the common case, not "drop its card"). Gated to `currentMode === 'first-person'`, the only mode `setPointerLockFilter`'s own gate ever lets the lock engage in. The dot itself (`#crosshair-dot` in `index.html`, the `crosshair` option on `ViewControllerOptions`) is a CSS `display` toggle driven by one method, `ViewController.updateCrosshair()`: shown only while the mode is first person AND `canvas.ownerDocument.pointerLockElement === canvas`, called after every mode change (`setMode`) and from a `pointerlockchange` listener (the lock engaging or releasing, including `setMode`'s own force-exit entering isometric or desk). Without the `crosshair` option at all, nothing is drawn — graceful degradation, the same rule `hint` already follows.

It never calls `runAction` and never moves DOM focus onto the button (so Enter cannot then send the request) — S7 keeps a write action behind a click. main.ts pairs it with `ViewController.refocus(agentId)` so F has a visible camera effect too.

### Keyboard triage (src/ui/TriageKeys.ts, main.ts)

Issue #85 adds N, F and / without touching WASD, Space, Q, Shift, O, I, Shift+L, Esc or ?. `handleTriageKey(event, { next, focus, filter })` is a pure dispatcher (one `window` `keydown` listener in main.ts): ignored over a form field (`SELECT`, `INPUT`, `TEXTAREA` or `isContentEditable`) or with Ctrl, Alt or Meta held, else `KeyN` calls `next`, `KeyF` calls `focus`, and `Slash` without Shift calls `preventDefault` (stops the browser's own quick find) then `filter` — Shift+Slash is `?` on a US layout, so the dispatcher leaves it alone and the Legend's own listener opens the legend instead. The same form-field check (now with `isContentEditable`) also guards `FreeCamera.ts`'s own `keydown` listener, `ViewController.ts`'s (O, I, Esc, the overview/isometric WASD pan) and `registry.ts`'s (Shift+L) — the triage filter is the app's first text field, so every global key listener needed the check, not only the new one. main.ts wires `next` to `triageQueue` + `nextInQueue` (`src/ui/attention.ts`) and `selectAgent`; `focus` to `ViewController.refocus(agentId)` (recenter on the current selection, or `selectAgent` the queue head when none) plus `AgentCard.pulseFocus()`; `filter` to `AgentPanel.expandPanel()` (opens a collapsed panel first) then `focusFilter()`.

### Label detail (src/ui/LabelDetail.ts, src/ui/LabelDeclutter.ts)

`labelDetail(facts, view)` is pure: mode `all` → full; selected, hovered or stuck → full in every view. A wait forces full differently by view (review fix, PR #152): overview or isometric force it only for a fresh wait (or an unknown wait time, the old behavior), so a real queue (14+ agents, almost all aging) does not force every label full and overlap the others (#132); first person keeps the original rule (any wait that is not cold forces full), since the issue that prompted the overview relief never described first person, and its own queue spacing (about 1.7 m) can already overlap on screen, where a nearby waiting agent must not go compact and lose its activity line. Outside a forced case: overview or isometric view (`isViewFromAbove`) → full when `zoomDistance <= OVERVIEW_FULL_LABEL_ZOOM` (14), else compact; first person → full within `FIRST_PERSON_FULL_LABEL_DISTANCE` (8) of the camera, else compact. `LabelDetailController` recomputes every `LABEL_DETAIL_INTERVAL_MS` (150 ms), on a selection change and after each poll. It only toggles the `compact` class on the label element (`applyLabelDetail`), so the label text, the BMAD persona names and the Codex tag stay as they are; the CSS hides `.activity` and shows a dot from `--agent-color` (set by `StickFigure`) and, when the agent waits, a short `.wait` chip (`formatWaitShort`, for example "12m") that the CSS hides in a full label (the activity line already spells out the wait) and shows in a compact one, so the wait time still reads once the label goes compact.

**Declutter (`LabelDeclutter.ts`, #132):** even a compact label is a fixed-size CSS2D overlay — unlike a room label (a sprite that scales with distance), it never shrinks when the camera pulls back. At a real queue's scale (14+ agents in a 12-unit room, viewed from a default overview that sits several rooms away), compact labels can still overlap each other. Declutter runs only in the overview and the isometric view (`isViewFromAbove`, review fix, PR #152): first person's own queue spacing can already overlap on screen, and a waiting agent you stand near must never disappear there, so it never hides a label in that view at all. `refresh()` runs in two passes so one refresh forces at most one browser layout pass, not one per agent (review fix, issue #168, from the #152 review comment): pass 1 sets every label's full/compact class (`applyLabelDetail`) and writes nothing else; pass 2, only when declutter runs at all, reads layout. In pass 2, `refresh()` projects each agent's label world point to a screen point (`projectToScreen`, the same NDC-to-pixel math `CSS2DRenderer` itself uses, built on `OffscreenMarker.ts`'s `projectToClip`); a point behind the camera, past the far plane, closer than the near plane (`tooClose`, review fix, issue #168 — the projection math right at that plane can divide by a near-zero view-space z), or outside the `[-1, 1]` NDC frustum returns no point and the agent never becomes a candidate at all, so it can never wrongly outrank one that is actually on screen. The candidate's `Rect` comes from the label element's own `getBoundingClientRect()` (measured once per agent in this pass, using the level pass 1 already set, so it reflects the real rendered box, long name included) and falls back to a fixed estimate per level (`FULL_LABEL_SIZE`, `COMPACT_LABEL_SIZE`) only when no real size exists (a test, or a label not yet laid out; review fix — the fixed box alone missed an overlap a long name's real width would catch). `labelPriority(facts)` ranks an agent, lower wins a tie: selected (0), hovered (1), a fresh wait or an unknown wait time (2, the same cases `blockedRecently` forces full for), stuck (3), an aging wait (4), a cold wait (5), any other busy agent (6), idle (7); a tie inside one rank goes to the longer wait. `declutterLabels(candidates)` is pure (rects and priorities in, a visible-id `Set` out, no stored state): in any cluster of overlapping rects only the highest-priority label stays, through one sort and a linear scan (0.0035 ms for 40 agents, measured) — cheap enough for every 150 ms refresh, never every frame. A label the declutter hides keeps its full/compact class; `applyLabelVisibility` only toggles `style.visibility`, so a label that stops overlapping (an agent moves, the camera moves, the higher-priority one leaves) returns on the very next `refresh()`, with nothing remembered from the last pass. `#labels=all` and the `all` mode skip declutter entirely, matching that mode's promise to show every label. The "N waiting" sign (`QUEUE_COUNT_SIGN`) is untouched: it is not a per-agent label, so it is never a declutter candidate and never hides.

Hover reuses `ViewController.pickAt` at the last pointer position, or the canvas center while the pointer is locked. The zoom comes from `ViewController.zoomDistance`. Key V cycles `smart` → `all` → `smart`; `#labels=all` starts in `all`; `#label-mode` in the side panel header shows the mode. With the `scene` option, the controller also shows or hides detail signs: CSS2D objects with `userData.detailSign = { rect, hoverOnly }` (war room title, lock and past sessions signs, the "You" sign). `signVisible`: mode `all` or pointer over the rect (floor raycast) → shown; `hoverOnly` → hidden otherwise; overview → shown at `zoomDistance <= OVERVIEW_SIGN_ZOOM` (24); first person → within `FIRST_PERSON_SIGN_DISTANCE` (12). It sets `style.visibility`, which CSS2DRenderer does not touch. Room labels (objects with `userData.roomRect`) follow `roomLabelVisible`: hidden in first person while the camera stands in their room, shown otherwise; the controller sets `visible` and calls `userData.applyView({ viewMode, zoomDistance, detail })` only when that changes, then the `changed` option (main.ts asks for a frame). The controller collects labels and signs once and again after `sceneChanged()` (main.ts calls it after each poll and world update), not on every refresh.

`src/scene/Selection.ts` holds the shared selection: `selectAgent(id)`, `clearSelection()`, `selectedAgentId()`, `onSelectionChange(cb)` (returns an unsubscribe function). Extensions and other UI (for example a triage list) use it. A click on a figure (raycast against the figure meshes) or on a row in the triage list selects; Esc clears, and so does a click that misses every figure (issue #133; a drag release is not that click, and a click while the first-person camera is locked looks around instead); an agent that leaves is deselected. On a new selection the camera flies to the agent in 0.6 s and `SelectionMarker.ts` draws a ring in the agent's color under it. `#select=<agent id>` (`#focus=`, its older name, still works) selects that agent once it appears.
